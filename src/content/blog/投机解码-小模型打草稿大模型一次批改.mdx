在[《图解大模型（入门篇）》](/blog/图解大模型-一口气搞懂大模型的骨架/)里我们算过一笔账：70B 参数的模型，FP16 权重约 140GB，一张 H100 SXM 的显存带宽约 3.35TB/s，自回归生成每个新词时，光把权重从显存搬到片上就要约 42ms。但这一步真正用于计算的时间只占零头——大部分时间 GPU 计算单元在**等数据从显存搬过来**。

既然每一步都有大把闲置算力，能不能让模型在这一趟搬运里**顺手多验证几个词**？这就是**投机解码（Speculative Decoding）**：让一个便宜的小模型先快速猜几个词（打草稿），大模型再一次性并行「批改」——对的收下，错的从出错处重来。

这篇讲四件事：**是什么（流程）→ 为什么答案不变（数学保证）→ 草稿从哪来（五种做法）→ 到底能快多少（算账）→ 工程上怎么落地 → 什么时候别用**。

## 1. 关键观察：这一趟权重，能顺便多带几个词吗？

要理解投机解码，先抓住「免费便车」成立的条件。

普通 Decode 一步做了两件事：把全部权重搬上芯片（约几十毫秒，数据搬运）+ 用这些权重对 1 个 token 做矩阵乘（几毫秒，计算）。瓶颈在搬运，计算单元大部分时间空着。如果在**同一趟搬运**里，让权重顺便去乘几个额外的 token，多花的只是几份很小的计算——这正是闲置的那部分算力。

但这个「顺便」有严格的适用边界，三个前提任意一条被打破，免费便车就不存在：

1. **得在 Decode 阶段。** 处理输入（Prefill）时，成百上千个 token 本来就在一起算，计算单元已经饱和，没有闲置算力可搭。
2. **batch 不能大。** 高并发时，权重的一趟搬运被很多请求分摊，计算单元逐渐被占满（系统从「带宽受限」转向「算力受限」）。这时额外候选会和其他请求抢计算。
3. **候选链不能太长。** 验证 $k+1$ 个位置时，注意力要读这些位置对应的 KV（长度约 $k$ 的一小段），$k$ 份投影矩阵也要算。链式候选 $k$ 在 3～7 时这些边际成本很小；树状候选几十上百个节点时，这部分计算就不可忽略了。

记住这三条——它们正好决定了第 7 节里「什么时候该开、什么时候该关」。

## 2. 一轮完整的流程：草稿 → 并行验证 → 截断

先认识两个角色：

- **草稿模型（draft，小模型）**：便宜、快，负责连续猜 $k$ 个候选词，这 $k$ 次是它自己串行的自回归（便宜的前向）；
- **目标模型（target，大模型）**：贵、慢但准，它不一个一个词地确认，而是对「最后一个已确认词 + $k$ 个草稿词」共 $k+1$ 个位置做**一次 Prefill 形态的并行前向**，一次拿到每个位置上目标模型自己的概率分布。

接下来是三步：

1. **草稿模型串行出 $k$ 个候选。** 比如大模型最后确认的词是「小猫追着它的尾巴」，小模型接着猜：「它」「的」「尾」。
2. **目标模型一次并行验证。** 它不用重新算前缀（前缀的 KV Cache 已在手边），一次算出「它、的、尾、bonus 位」四个位置的目标分布。
3. **从左到右概率抽检。** 遇到第一个没通过抽检的位置就停下：
   - **中途有词被拒**：前面通过的全部收下，**在拒绝位置补一个词（补抽）**——这一步等于把草稿抽偏的那一下作废，让大模型按自己的概率**重新选一个词**，而不是随便挑、也不是取概率最高的词。严格说，重选用的不是大模型的完整分布，而是「扣掉草稿已经占掉的那部分概率之后」剩下的分布（叫**修正分布**，第 3.1 节给公式）；直觉上可以先理解成「主编不认可实习编辑写的这句，自己按想法接一句」。被拒词后面的所有草稿一律丢弃（左边的词作废，右侧打分连带失效）；
   - **$k$ 个草稿全通过**：第 $k+1$ 个位置（最后一个草稿位置）的分布验证前向里已经顺手算出来了，从中白送采样 1 个 **bonus token**——不额外调用大模型。所以链式 $k=3$ 时，一轮最多落下 **4 个词**（3 个草稿 + 1 个 bonus）。

补词用的是本次验证前向已经算好的分布，**不需要再跑一次大模型**；已确认前缀的目标模型 KV 沿当前轮直接沿用，只有拒绝位之后的草稿 KV 被回收。

> 类比：实习编辑一口气写 $k$ 句，主编一次通读整段签发；读到第一个不能放行的句子，后面的稿子全部退回重写。主编手里还多发一枚「签完顺手补一句」的奖励 token。三条失灵声明：草稿编辑写稿要花串行时间；高并发时主编没有空当；候选太长时验证本身变贵。

这套机制最反直觉的一点是：**模型每一步实际「选择」词的规则都变了（不是直接取目标模型的 argmax 或采样），最终输出的分布却和「目标模型单独生成」严格相同。** 凭什么？

## 3. 为什么输出分布不变：一套概率抽检

### 3.1 随机采样下的规则

设目标模型在某个词上的概率为 $p(x)$，草稿模型为 $q(x)$。草稿提出的词按下面的规则被接受：

$$
\text{以概率 }\min\!\left(1,\frac{p(x)}{q(x)}\right)\text{ 接受 }x
$$

直觉：

- 草稿觉得这个词**比目标还可能**（$q\ge p$，比值 $\le1$）时，一定放行（概率 1）；
- 草稿觉得它**没目标那么有把握**（$q<p$），按 $p/q$ 的折扣概率放行——草稿越低估它，越要靠掷硬币补回来。

第 2 步说的「补抽」，用的就是下面这个分布——把草稿已经占掉的概率扣掉，只在剩余部分里重选，这叫**修正分布**（也叫残差分布）：

$$
p'(x)=\frac{\max(0,\,p(x)-q(x))}{\sum_y \max(0,\,p(y)-q(y))}
$$

符号读法：$x$ 是当前要补的那一个词；$y$ 是求和用的临时变量，代表词表里**任意一个词**，$\sum_y$ 表示让 $y$ 遍历整个词表（几万万个词各算一次、再加起来，实际只有少数词非零）。分母算的是「目标总体上比草稿多出多少概率」；分子那一列加起来通常小于 1、不能直接当概率，除以分母归一化后总和才等于 1。即：**目标比草稿多出的那部分概率，按各词被低估的程度分回去**。

用[《思维链》](/blog/思维链-大模型为什么要先想再答/)里的 3 个词手算一遍（$p$：很 0.7 / 真 0.2 / 不 0.1；$q$：很 0.5 / 真 0.3 / 不 0.2）：

| 词 | 目标 $p$ | 草稿 $q$ | 接受概率 $\min(1,p/q)$ |
| --- | --- | --- | --- |
| $x_1$ 很 | 0.7 | 0.5 | 1.00 |
| $x_2$ 真 | 0.2 | 0.3 | 0.67 |
| $x_3$ 不 | 0.1 | 0.2 | 0.50 |

最终 $x_1$ 出现的边际概率：草稿直接通过的 $0.5$，加上草稿采了别的词、被拒绝后从修正分布补抽到 $x_1$ 的通道 $0.2$，合计 $0.7=p(x_1)$。$x_2$、$x_3$ 同理恰好为 $0.2$、$0.1$。

**为什么需要修正分布？** 草稿在 $q>p$ 的词上「多占」了概率份额（比如「真」被草稿选中的频率 0.3 高于目标的 0.2），多占的部分必须原样吐回来；这些份额就从「目标比草稿多出的部分」$(p-q)_+$ 里补抽。残差分布保证：**草稿高看的词不会被过度代表，草稿漏掉的词仍有「被拒绝→补抽」通道**。换个说法，一次拒绝+补抽，等价于把草稿抽偏的那一下，按目标分布**重抽一次**。

<SpecConserveFigure />

*图 4：抽检通过的是 $\min(p,q)$ 段，拒绝后补抽 $(p-q)_+$；两段拼起来恰好等于 $p$。*

<Expand title="展开推导：三行得到「草稿 + 修正 = 目标」">

记所有词抽检通过的总概率为 $\sum_x\min(p(x),q(x))$。一个词最终输出的概率 = 草稿被接受 $q(x)\min(1,p/q)=\min(p(x),q(x))$，加上走到补抽（概率 $1-\sum_y\min(p_y,q_y)=\sum_y(p_y-q_y)_+$）再以归一化的 $(p-q)_+$ 补出：

$$
\min(p(x),q(x))+\Big[\sum_y(p(y)-q(y))_+\Big]\frac{(p(x)-q(x))_+}{\sum_y(p(y)-q(y))_+}=p(x)
$$

所以「草稿先试、被拒再补」这个两步机制，在分布上与直接从 $p$ 采样完全等价。

</Expand>

### 3.2 贪心模式：规则更简单

如果推理时根本不采样——每一步都选概率最高的词（**贪心解码，greedy decoding**）——规则可以简化成「逐位对答案」：

> 草稿词与目标模型在该位置的 argmax（概率最高的词）**一致就收，遇到第一个不一致就停**，并取目标模型的 argmax 作为补词。

这是上面随机规则的确定性特例：贪心场景没有「分布」要保持，只要前缀每一步都是目标自己也会选的词，接多长都不改变贪心结果；第一个分歧处换成目标的选择即可。本文第 7 节讲开关决策时会用到它。

### 3.3 两个工程注记

- **为什么要求草稿和目标定义在同一个词表上**：$p$、$q$ 必须是对同一组词的概率分布，比值和相减才有意义。工程上最省事的是同族的大小模型（如 7B 配 70B）；跨词表可以做 token ID 映射，或用 TLI/SLEM 这类异构词表方案。
- **理论无损，工程有数值注记**：真实引擎里浮点精度、batch 大小变化会带来 ULP 级差异，开启投机和关闭的输出不保证逐 token 完全相同；分布层面的等价性不受影响。

讲完「答案为什么不变」，自然进入下一个问题：**这些便宜的草稿，到底是谁写的？**

## 4. 草稿从哪来：五种典型做法

所有方案都在回答同一个问题：**便宜的候选 token，谁来出？** 按「要不要额外模型」分，有零模型、小模型、挂小头、原生模块四大类。

### 4.1 Prompt Lookup：零模型，从输入里「抄」

[Prompt Lookup Decoding](https://github.com/apl-casals/prompt-lookup-decoding) 不需要任何草稿模型：当前缀里出现过某段文字时，直接把后面的 $n-1$ 个词当候选（n-gram 匹配）。它在**代码补全、文档复述、引用上文**场景命中率高——这些任务本来就有大量重复文本。vLLM 的 `ngram` 方法、Transformers 的 prompt-lookup 就是它。

### 4.2 独立小模型：7B 给 70B 打草稿

经典 Speculative Decoding（[Leviathan et al., ICML 2023](https://proceedings.mlr.press/v202/leviathan23a.html)）用一个独立训练的小模型串行出 $k$ 个候选。工程上有两条要求：**同一词表**（否则要做 ID 映射）；草稿模型也要有自己的权重和 KV Cache（见 6.1）。草稿模型不必同族，但「分布越接近目标、且足够便宜」收益越大——实践中 7B 配 70B 是常见搭配。

### 4.3 Medusa：在大模型头上挂几个「预测头」

[Medusa](https://arxiv.org/abs/2401.10774) 不另起模型，而是在目标模型的顶层**额外训练多个解码头**：第 1 个头预测下一个词、第 2 个头直接预测第 2 个词……多个头并行给出一棵候选树，配合树状掩码一次验证。默认的 typical acceptance 是近似无损口径，标准拒绝采样才严格无损。它的草稿头很小，但要为特定目标模型训练。

### 4.4 EAGLE：让草稿头「看着特征和词」猜

[EAGLE](https://arxiv.org/abs/2401.15077) / EAGLE-2/3 的草稿头吃的是**目标模型倒数第二层的隐藏特征 + token embedding**，而不是只看 token ID：草稿头在「特征序列」上做自回归，等于看着大模型的「内心草稿」往下猜，命中率比纯 token 方案高很多。官方仓报告 Vicuna 口径平均接受长度约 2.45（EAGLE-1）到 3.5 上下（EAGLE-3）。同样是小头方案，一套头只能配一个目标模型，头和目标版本要一起维护。

### 4.5 MTP：模型出厂自带的预测模块

[DeepSeek-V3 的 MTP](https://arxiv.org/abs/2412.19437) 把「多 token 预测头」直接做进模型并联合训练（详见[注意力机制演进](/blog/注意力机制演进-从mha到gqa与mla/)中 MTP 一节）。推理时这个模块可以直接当 proposer，和主干共享 embedding 与输出头，是「训练目标即推理草稿器」的做法。

| 方法 | 草稿来源 | 额外模型 | 额外训练 | 严格无损口径 |
| --- | --- | --- | --- | --- |
| Prompt Lookup | prompt/已生成文本中的 n-gram | 无 | 无 | 贪心/采样框架下均可 |
| 经典 Speculative Decoding | 独立小模型 | 是（小权重） | 否 | 标准拒绝采样 |
| Medusa | 目标上的多个解码头 | 无独立模型 | 需训练头 | 标准 RS 无损；typical 近似 |
| EAGLE-1/2/3 | 吃隐藏特征+embedding 的轻量头 | 无独立模型 | 需训练头 | 配标准拒绝采样 |
| DeepSeek MTP | 训练在模型里的预测模块 | 无（共享主干） | 联合训练 | 配目标校验 |

账本先放这儿：**草稿越准、越便宜，加速越多；草稿再聪明，如果验证太贵或场景不对，也可能倒亏。** 下面算这笔账。

## 5. 加速这笔账：能落几个词、花多少时间、实测多少

加速比不是拍脑袋的倍数，要分三层算：**一轮平均落下几个词 → 这一轮花了多少时间 → 真实系统实测多少**。

### 5.1 一轮平均落下几个词

设每个草稿词被接受的平均概率为 $\alpha$，假设各位置接受率近似独立：

- 第 1 个草稿被接受的概率是 $\alpha$，第 2 个是 $\alpha^2$……
- 每轮的期望产出（含拒绝位的修正词，那个位置必落 1 个）为：

$$
\mathrm{E}[L]=1+\alpha+\alpha^2+\dots+\alpha^k=\frac{1-\alpha^{k+1}}{1-\alpha}
$$

$k=3$ 时：

| $\alpha$ | 0.6 | 0.8 | 0.9 |
| --- | --- | --- | --- |
| 每轮期望落词 $\mathrm{E}[L]$ | 1.96 | 3.36 | 4.10（受 $k+1$ 封顶） |

注意 $\alpha^{k+1}$ 项：它对应「$k$ 个草稿全中」的概率——这时才有 bonus 词。这不是加速比：9 个格子是「每轮落下的词数」，不是「快了多少倍」，也不是「快 6 倍速」。

### 5.2 这一轮花了多少时间

普通生成 $\mathrm{E}[L]$ 个词，目标模型要跑 $\mathrm{E}[L]$ 次 Decode 步；投机解码一轮的实际耗时 $\approx k\cdot\tau_d + \tau_v$：

- $\tau_d$：草稿模型单步（$k$ 次便宜的串行前向）；
- $\tau_v$：目标的一次验证前向（Prefill 形态，对 $k+1$ 个位置）。

墙钟加速比近似：

$$
S\approx\frac{\mathrm{E}[L]}{k\cdot c+r},\qquad c=\frac{\tau_d}{\tau_t},\ r=\frac{\tau_v}{\tau_t}
$$

其中 $\tau_t$ 是目标普通 Decode 单步耗时。$c$（草稿有多便宜）和 $r$（验证有多贵）决定分母。**为什么草稿必须又快又小**：它的 $k$ 次前向是真金白银花在关键路径上的。拿 7B 配 70B 的典型比例举例：$c\approx0.15$（草稿单步约为目标的 15%）、$r\approx1.2$，$\alpha=0.8$、$k=5$ 时 $\mathrm{E}[L]\approx3.8$，$S\approx 3.8/(0.75+1.2)\approx1.9$ 倍左右；同样参数下 $\alpha=0.9$、$k=8$ 约 $2.7$ 倍。

### 5.3 真实系统里是多少

- vLLM 官方博客在 QPS=1 时，独立草稿约 **1.5×**、ngram 摘要类最高约 **2.8×**；
- EAGLE 官方仓在 MT-Bench 等对话基准报告平均接受长度约 2.45（EAGLE-1）/ 3.5（EAGLE-3），常见整体加速 2～3.5 倍；
- **常见收益落在 1.5～3×**，不是随处 6 倍。它随任务接受率、生成长度、温度、batch 大小而变；Snell 等人的 test-time compute 研究也表明，收益不是单调的。

<Expand title="折叠：为什么高并发下收益会衰减甚至倒亏">

进入算力受限期后，验证计算和其他请求抢资源：vLLM 官方博客实测高 QPS 时部分配置吞吐降到不开时的 55%～70%。被拒的草稿是白算的废计算（还要占临时 KV），草稿被接受得越长，这些临时 KV 越占地方。所以**投机解码省的是单流延迟和闲置算力，不是「无条件提升总吞吐」**。

</Expand>

账算完了。要把这笔账在真实引擎里兑现，还要解决几个工程问题。

## 6. 工程上怎么跑快

### 6.1 权重与 KV：「两套」到底是谁的两套

「两套 KV」只适用于**独立草稿模型**方案（4.2）：它和目标是两个不同的模型，各有一份权重、各有一套 KV Cache——草稿写草稿的、目标算目标的。头式方案则不是这样：

- **Medusa / EAGLE**：只有一套目标模型权重和它的 KV，小预测头挂在目标层上，头自身只有很小的状态；草稿过程中读的是目标的隐藏特征；
- **MTP**：预测模块与主干共享 embedding 和输出头，KV 也随主干；
- **所有方案共同的一点**：一轮验证结束后，**被接受位置的目标 KV 直接留下复用**；草稿侧的临时 KV、树分支上没选中的 KV 全部释放回块池（分页块的生命周期见 [PagedAttention](/blog/pagedattention-给kv-cache装上虚拟内存/)）。

所以「维护两套模型很占显存」这句话，只对「7B 配 70B」的独立草稿成立；头式方案的额外显存很小。

### 6.2 从一条链到一棵树：tree attention

第 2 节的标准流程，$k$ 个候选是**一条链**：第 2 个草稿建立在第 1 个之上。问题是第 2 个词猜错，后面算得再好也全部作废——一条路太容易断。

**树状验证（tree attention）**让草稿器一次提出一棵候选树：从同一个前缀分出几条岔路（比如 d2 可以是 d2a 或 d2b），目标模型用一个**树状因果掩码**保证分叉之间互偷看，却**在一次前向里把树上所有节点都验证完**；哪条路径从根开始连续通过，就接哪条。SpecInfer、Medusa、EAGLE 都用树。代价是树越宽，6.1 说的临时 KV 和验证计算越大——树宽是拿计算换命中率。

### 6.3 验证前向怎么调度

第 2 节说过，目标的验证前向是 **Prefill 形态**（一次吃 $1+k$ 个位置），不是 Decode。引擎靠 **chunked prefill** 把它切成小块、和其他请求的正常 Decode 步混在同一批里执行（详见[一次推理的旅程](/blog/一次推理的旅程-prefill与decode/)第 7 节），避免一次大验证阻塞全队。这也是第 1 节「Prefill 阶段没有便车」的工程含义：投机给 Decode 加活，混批调度负责把活摊平。

### 6.4 显存与容量的两笔账

除了 6.1 的常驻权重，提案 token 还会瞬时占用目标 KV 池：树宽 40～128 个候选时尤其明显。它压低的是能同时服务的请求数。这部分细节与 PagedAttention 的块回收、前缀共享是同一套机制，这里不再展开。

工程账清楚之后，最后一个问题最实际：**什么时候根本不该开它？**

## 7. 什么时候不用，以及怎么决策

### 7.1 不赚甚至倒亏的场景

- **高并发 / 大批量**：进入算力受限期（第 1 节前提 2 被打破），废提案拖慢整体（实测 55%～70% 吞吐的配置见 5.3）。生产上通常按负载动态开关；
- **发散创作、高温采样**：草稿命中的是「最常规的延续」，温度越高、答案越发散，$\alpha$ 越低；
- **短会话 / 短输出**：草稿权重和树 KV 的常驻成本摊不平；
- **长链思维链上的朴素 token 草稿**：推理轨迹多解，token 级 exact-match 误杀率高（[SCoT 论文](https://arxiv.org/abs/2504.19095)报告超过 5k token 的难题上外挂草稿反而更慢）；有效的做法是原生 MTP 或「思考段落」粒度的草稿。

### 7.2 贪心用户

如果你的服务本来就用贪心解码（3.2），决策更简单：不需要概率抽检那套机制，逐位对 argmax 即可，工程实现和核对都更直接；规则本身不变（前缀一致才收）。

### 7.3 决策盒

| 场景 | 建议 |
| --- | --- |
| 低并发交互 / 代码 / 模板化文本 / RAG 复述 / 长输出 | 开：n-gram 零成本先试，或 EAGLE/原生 MTP |
| 高并发吞吐服务 | 先压测；按 QPS 动态开关注销，别默认全开 |
| 发散写作、高温、短会话、超长开放推理 | 关，或只在模型自带原生草稿头时小预算试 |
| 离线批处理（没有延迟 SLA） | 通常关，把算力留给总吞吐 |

它和其他推理优化也不是替代关系：

| 技术 | 压的是什么 | 和投机解码 |
| --- | --- | --- |
| 量化 / GQA / FlashAttention / PagedAttention | 单次权重搬运、注意力或显存开销 | 让 $\tau_v$、$\tau_d$ 更小，**可叠加且常互相增强** |
| Continuous batching / PD 分离 | 调度与部署形态 | 高负载下需要调度协同 |

一句话：**投机解码用「草稿的串行小成本 + 一次并行验证」换「少搬几遍权重」，它优化的是 Decode 阶段的单流延迟——前提是那趟权重上本来就有闲置算力。**

## 8. 自测（答案点击展开）

<Expand title="Q1：为什么在 prefill 阶段或高并发 batch 下，投机解码通常没有收益？">
prefill 阶段 $n$ 个输入位置本来就并行计算，算力已饱和，没有闲置算力可搭；高并发时一趟权重搬运被很多请求分摊，系统从带宽受限转向算力受限，额外候选要和其他请求抢计算，被拒草稿还成为纯废算，可能降低总吞吐。
</Expand>

<Expand title="Q2：k 个草稿全部被接受时，一轮最多落几个词？为什么能多拿一个？">
$k+1$ 个：$k$ 个草稿，加上第 $k+1$ 位置的 bonus token。bonus 用的是同一次验证前向里最后一个位置已经算好的目标分布，不需要再跑一次大模型。
</Expand>

<Expand title="Q3：拒绝采样为什么能让输出分布与目标模型完全一致？">
草稿在 $q\ge p$ 的词上多占的概率，通过「按 $p/q$ 折扣放行」被削平；草稿低估（$p>q$）的词，在拒绝后从归一化的残差分布 $(p-q)_+$ 补抽。两者相加每个词的边际概率恰好等于 $p(x)$（见折叠推导）。
</Expand>

<Expand title="Q4：贪心解码时接受规则是什么？和采样规则什么关系？">
逐位比较草稿词与目标模型在该位置的 argmax：一致就收，第一个分歧处停止并取目标的 argmax。它是随机拒绝采样在「不采样、每步取最优」场景下的确定性特例，不需要保持概率分布（答案本就唯一）。
</Expand>

<Expand title="Q5：独立小模型、Medusa、MTP 都「需要两套 KV Cache」吗？">
不是。只有独立草稿模型是两套权重两套 KV；Medusa/EAGLE 是目标模型上的小预测头，读目标的隐藏特征，额外 KV 很小；MTP 与主干共享 embedding/输出头。所有方案里，被接受位置的目标 KV 都会留下复用，草稿和落选分支的临时 KV 在每轮后释放。
</Expand>
