注意力（Attention）是 Transformer 的核心，也是这些年大模型架构里**演进最活跃**的部分。回看 2017 年至今的改进，基本围绕三条主线（与图 1 对应）：

1. **让它更准、更好算**（精确、高效计算）——FlashAttention、Ring Attention；
2. **让它能处理更长序列**（近似降复杂度）——稀疏注意力、线性注意力、原生稀疏 NSA；
3. **让它推理更省显存、吞吐更高**（压缩 KV Cache）——MQA、GQA、MLA。

下面就按 ① → ② → ③ 的顺序讲，和图 1 完全对应；偏学术的深推导放在扩展阅读。

*图 1：三条主线沿时间轴（向右）发展——① 基础与高效计算（蓝，精确）；② 降复杂度的稀疏/线性（紫，近似，思想被 NSA 继承）；③ 省 KV Cache 的共享/低秩（绿，推理工程主流）。*

## 1. 起点：Scaled Dot-Product 与 MHA

标准注意力（公式、点积即相似度、为什么除 $\sqrt{d_k}$、因果掩码）在 [图解 Transformer](/llm/) 里已详细讲过，这里只回顾骨架：

$$
\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
$$

**多头**（MHA, Multi-Head Attention） 把向量切成 $h$ 个头、各头在不同子空间独立做注意力再拼回：

$$
\mathrm{MHA}(Q,K,V)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)W^{O},\quad \mathrm{head}_i=\mathrm{Attn}(QW_i^Q,KW_i^K,VW_i^V)
$$

每个头都要存自己的一份 K、V——这正是推理时 **KV Cache** 的来源，也是后面"省显存"改进的靶点。

**两个痛点**（对应三条主线要解决的问题）：

- **计算/显存随序列长度二次增长**：注意力分数是 $n\times n$ 矩阵，$O(n^2)$；
- **KV Cache 随层数、头数、上下文线性膨胀**：长上下文/高并发时显存被它占满。

接下来的三条主线，分别从「怎么算得更快（①，不改结果）」「少算一些（②，近似）」「缓存压缩（③，不改结果）」来优化。

## 2. 主线① 精确、更好算：FlashAttention 与 Ring Attention

这一类**不改变注意力的计算结果**（数学上等价），只优化它在硬件上**怎么算**。

- **FlashAttention**（2022/2023）：传统实现反复在显存和 SRAM 之间读写巨大的 $n\times n$ 注意力矩阵，很慢很费显存。FlashAttention 用**分块（tiling）+ 在线 softmax**，一块一块地算注意力并累积，**从不把完整的 $n\times n$ 矩阵写回显存**（IO 感知）。结果和标准注意力完全一致，但显著加速、省显存，已成为训练/推理底层默认。
- **Ring Attention**（2023）：把超长序列的 K/V **分块放在多张卡上**，各卡环形传递 K/V 块、边传边算，让超过单卡显存的超长序列可以分布式计算，计算结果同样精确。

> 关键直觉：这两个方法**没有动注意力公式**，只是让同样的计算更适合 GPU/多卡。所以它们可以和 GQA/MLA、量化等叠加使用。

## 3. 主线② 降复杂度：稀疏与线性注意力（长序列，近似）

标准注意力的代价有两块：$n^2$ 个注意力分数（算力）和随 $n$ 增长的 KV Cache（显存）。这两类方法分别从两条路降成本，**都是近似**（结果不再严格等于完整 softmax）。

### 3.1 稀疏注意力：少看一些位置

思路最直观：不是每个 token 都看全部历史，只让它看一部分位置，复杂度从 $O(n^2)$ 降到 $O(n\cdot w)$（$w$ 是每 token 看的位置数）。

- **滑动窗口（sliding window）**：每个 token 只看前面最近的 $w$ 个位置。局部依赖够用、长程依赖丢失；Mistral 把它和少量全局注意力结合用于长上下文。
- **全局 token（global）**：选少量特殊位置（如分类符 CLS）能看到所有位置、也被所有位置看到，补上长程通道。
- **Longformer**（2020）= 滑窗 + 全局；**BigBird / Sparse Transformer** = 滑窗 + 全局 + 随机/块稀疏（后者在理论上保持了序列模型的表达能力）。

### 3.2 线性注意力：不存 KV，改存一个固定大小的状态

这是和稀疏完全不同的一条路。标准注意力是「先算 $n\times n$ 的权重矩阵，再加权 V」：

$$
O=\mathrm{softmax}(QK^\top)V
$$

线性注意力先用一个非负特征映射 $\phi(\cdot)$ 替换 softmax（去掉指数归一化的强耦合），再用矩阵乘法结合律改变计算顺序：

$$
O=\phi(Q)\underbrace{\big(\phi(K)^\top V\big)}_{\text{固定大小的状态矩阵}}
$$

关键在括号里的 $\phi(K)^\top V$：它的形状是 $d_k\times d_v$，**与序列长度 $n$ 无关**。于是它可以像 RNN 一样**递推维护**——每来一个新 token，只做一次固定大小的矩阵外积累加，既不用算 $n^2$ 权重，也不用逐 token 缓存 K/V，复杂度降到 $O(n)$。代表工作：**Linformer**（沿长度维低秩投影）、**Performer**（用随机特征近似 softmax 核）。

线性注意力早年输给 softmax 的原因也很清楚：特征映射的近似损失语言建模质量，长程检索能力弱。但「固定状态、不存 KV」的性质在 2025 年后被门控/差分规则救活，成为 2026 年混合架构的一块（见 3.4）。

### 3.3 走向生产：NSA 原生稀疏

**原生稀疏注意力 NSA**（DeepSeek，2025，[arXiv:2502.11089](https://arxiv.org/abs/2502.11089)）把稀疏从「外挂近似」做成**从头原生训练**，三个分支加权：

1. **压缩分支（compression）**：把邻近 KV 块压成粗粒度表示，负责远距离的概览；
2. **块选择分支（block selection）**：用一个轻量打分器按相关性挑选最重要的若干块，负责精确取回；
3. **滑动窗口分支（sliding window）**：保留局部细节，保证近程不丢信息。

长序列推理近线性且效果接近稠密注意力。它是 **块级（block-wise）选择**，2025 年底产品化时进一步细化为 token 级的 DSA。

### 3.4 2025–2026：稀疏检索与线性状态的产品化

到 2026 年，降复杂度路线在旗舰模型上落地为三种「读取 KV 的方式」。先钉死一个最容易混的边界——**它们对 KV Cache 的处理根本不同**：

| 路线 | 逐 token 的 KV 还存吗 | 怎么用历史 | 代表 |
| --- | --- | --- | --- |
| 精确（GQA/MLA） | 存（MLA 存压缩潜变量） | 全部读取 | LLaMA/Qwen2、DeepSeek-V3 |
| **稀疏检索** | **存，完整保留** | 用索引器只取 top-k | **DSA、QSA、NSA** |
| **线性状态** | **不存**，只存固定大小状态矩阵 | $q^\top S$ 读状态 | **GDN、KDA** |

**稀疏检索派（KV 还在，挑着读）：**

- **DSA（DeepSeek Sparse Attention）**：DeepSeek-V3.2（2025-09 实验版、2025-12 正式版，[arXiv:2512.02556](https://arxiv.org/abs/2512.02556)）用 lightning indexer（闪电索引器）给历史条目打分、做**细粒度 token 级 top-k（$k=2048$）**，并实例化在 MLA 的 MQA 模式上——每个压缩潜变量条目被该 query 的所有注意力头共享，选择只做一次。它**不是 NSA 改名**：NSA 是块级三分支研究原型，DSA 是 token 级产品设计。智谱 **GLM-5**（2026-02，[arXiv:2602.15763](https://arxiv.org/abs/2602.15763)）直接采用同一个 DSA（论文明确引用 V3.2，不是同名巧合）。
- **QSA（Qwen Sparse Attention）**：Qwen3.8-Flash-Next（2026-08，[arXiv:2608.30320](https://arxiv.org/abs/2608.30320)）的稀疏层，micro-block 粒度配轻量压缩索引器（budget 2048、压缩比 4），每 4 层插 1 层。
- **DeepSeek-V4-Flash**（2026-04，[arXiv:2606.19348](https://arxiv.org/abs/2606.19348)）更激进：**CSA（Compressed Sparse Attention，沿序列维压缩后再稀疏选择）与 HCA（Heavily Compressed Attention，强压缩但保持稠密读取）交错**，再加滑动窗口与 on-disk KV；官方模型卡称 1M 上下文下 KV 约为 V3.2 的 7%。

**线性状态派（不存 KV，存状态）：**

生产级实现是 **Gated DeltaNet（GDN，[arXiv:2412.06464](https://arxiv.org/abs/2412.06464)，ICLR 2025）**。它把线性注意力的固定状态改成门控差分递推：

$$
S_t=\alpha\,S_{t-1}(I-\beta k_t k_t^\top)+\beta\,v_t k_t^\top
$$

每层只维护一个与序列长度无关的状态矩阵，decode 时用 $q_t^\top S_t$ 读出；门控 $\alpha$ 控制旧记忆衰减、$\beta$ 控制写入强度，差分项让状态能「擦写」旧值。代价是旧 token 被衰减/覆盖、**无法精确定位任意历史位置**，所以纯线性层必须周期性插入精确或稀疏注意力层兜底检索。**KDA（Kimi Delta Attention）** 是月之暗面 Kimi Linear 技术线同源的线性注意力，用在 GLM-5.3-Flash 里。

于是 2026 年的前沿模型都是**混合栈**（线性状态层便宜且显存恒定 + 稀疏/精确层保证检索），而且权重已开源：

| 模型（开源时间） | 层结构 | KV/状态形态 |
| --- | --- | --- |
| Qwen3-Next-80B-A3B（2025-09） | 36 GDN + 12 Gated Attention | 固定状态 + 常规 KV |
| Qwen3.5-397B-A17B（2026-02） | 45 GDN + 15 全注意力 | 固定状态 + 常规 KV |
| Qwen3.8-Flash-Next 125B（2026-08） | 3/4 GDN + 1/4 QSA | 固定状态 + 稀疏 KV（官方 **FlashQLA** kernel） |
| DeepSeek-V3.2（2025-12） | MLA + DSA | 压缩潜变量 + top-k 读取（**FlashMLA** 稀疏 kernel） |
| GLM-5 744B（2026-02） | MLA + DSA（同 DeepSeek 的 DSA） | 同 V3.2 |
| GLM-5.3-Flash 320B（2026-08） | 34 层 KDA + 11 层 KPool-DSA | 固定状态 + 稀疏潜变量（FLA / FlashMLA） |

<AttnHybridFigure />

*图（示意）：2026 年前沿模型按层交错三类注意力——线性状态层（显存不随上下文增长）、稀疏检索层（KV 还在但只读 top-k）、精确层（GQA/MLA 兜底）；层数比例各模型不同。*

工程结论一句话：**稀疏 = KV 还在但少读，线性 = KV 不存改存固定状态，两者都用效果换长度/显存，且都依赖专用 kernel（FlashMLA、FlashQLA、FLA），不是换个配置就能跑。**

## 4. 主线③ 省 KV Cache：MQA → GQA → MLA（推理工程主流）

这一类也**不改变注意力结果**（数学等价），而是压缩推理时要缓存/搬移的 K、V。

### 4.1 MQA 与 GQA：共享 K/V 头

<AttnShareFigure />

*图 2：从 MHA 到 GQA 再到 MQA，K/V 头逐渐合并、共享给更多 Q 头，KV Cache 随之缩小，精度损失很小。*

| 机制 | K/V 头数 | 效果 | 代表模型 |
| --- | --- | --- | --- |
| **MHA**（2017） | 与 Q 头相同（如 32） | 表达力最强、KV Cache 最大 | 原版 Transformer、GPT-2/3 |
| **MQA**（2019，Multi-Query） | **1** 组，所有 Q 头共享 | KV Cache 最小、加速最猛，但质量略降、训练易不稳 | PaLM、Falcon |
| **GQA**（2023，Grouped-Query） | 分组（如 8 组，每组 4 个 Q 头共享） | **质量≈MHA、速度≈MQA 的折中** | **LLaMA-2/3、Mistral、Qwen2+、GLM-4、DeepSeek、Gemini** |

**数学上**：MHA 每个 Q 头有独立投影出的 $K_i,V_i$（共 $h$ 份）；GQA 只投影出 $g$ 组 $K,V$（$g<h$），让若干 Q 头共享同一组已投影好的 $K_{g(i)},V_{g(i)}$：

$$
\mathrm{head}_i=\mathrm{Attn}(QW_i^Q,\ K_{\,g(i)},\ V_{\,g(i)}),\qquad g(i)=\Big\lfloor i\cdot \frac{g}{h}\Big\rfloor
$$

$g=h$ 退化为 MHA、$g=1$ 退化为 MQA，中间就是 GQA。KV Cache 里的 K/V 张量从「层数 × 头数 × …」降为「层数 × 组数 × …」。

**实践结论**：GQA 几乎不掉点地大幅降低 KV Cache、提升吞吐，是 2023 年后**几乎所有开源/国产 LLM 的标配**；MQA 因训练稳定性顾虑多被 GQA 取代。

### 4.2 国产集大成：DeepSeek MLA（低秩潜变量）

GQA 是"减少 K/V 头数"，DeepSeek-V2（2024）的 **MLA**（Multi-head Latent Attention，多头潜在注意力） 更进一步：**把 K、V 本身压成一个低维潜向量再缓存**。

<MlaFigure />

*图 3：MLA 不缓存完整 K/V，而是把高维隐藏状态 $h$ 下投影成低维潜向量 $c_t$ 缓存；用到时再上投影恢复 K、V。缓存的是 $c_t$，维度远小于完整 KV。*

**原理与数学**：

1. 隐藏状态 $h_t$（维度 $d$）先**下投影**成低维潜向量 $c_t$（维度 $d_c \ll d$）：

$$
c_t = W^{DKV}\,h_t
$$

2. **推理时只缓存 $c_t$**（而不是每层大份的 K、V）——这是 KV Cache 大幅缩小的关键；
3. 用到时再**上投影**恢复各头的 K、V：

$$
k_t = W^{UK}c_t,\qquad v_t = W^{UV}c_t
$$

4. **RoPE 位置编码解耦**（Decoupled RoPE）：位置旋转不能直接压进低秩潜向量（会破坏压缩），MLA 把 Q/K 拆成「内容部分」（走低秩压缩恢复）和「位置部分」（一小部分维度单独承载 RoPE、直接拼接），既保住相对位置感知又不牺牲压缩率。

| 对比（直觉） | 缓存内容 | 压缩思路 | 代表 |
| --- | --- | --- | --- |
| MHA | 完整 K、V（每头一份） | 不压缩 | 早期模型 |
| GQA | 分组后的 K、V | 减少头数（共享） | LLaMA / Qwen / GLM |
| **MLA** | **低维潜向量 $c_t$** | **低秩压缩 K/V 本身**，用时再展开 | **DeepSeek-V2/V3/R1** |

MLA 通常能在与 GQA 相近甚至更好的效果下把 KV Cache 压得更小，是目前"省 KV"最激进、最受关注的工程方案之一。

## 5. 位置编码的配合

注意力演进与位置编码紧密相关：绝对位置 → 相对位置 → **RoPE**（旋转位置编码，LLaMA/Qwen/DeepSeek 标配）与 **ALiBi**（线性偏置，BLOOM 等）。RoPE 让注意力天然感知相对位置，也直接影响了 MLA 的"解耦"设计。这部分在 [图解 Transformer](/llm/) 的位置编码扩展有专门讲解。

## 6. 全景对比与选型

下表按「解决什么问题 / 改不改变计算结果」组织，一眼看清每个方法的定位：

| 方法 | 年份 | 属于主线 | 解决什么问题 | 改变计算结果？ | 核心思想 | 代表模型 |
| --- | --- | --- | --- | --- | --- | --- |
| MHA | 2017 | 起点 | ——（基线） | —— | 多头点积注意力 | Transformer / GPT-2 |
| FlashAttention | 2022 | ① 精确高效 | 算得快/省显存 | **不改变**（精确） | 分块 + 在线 softmax，IO 感知 | 几乎所有训练/推理 |
| Ring Attention | 2023 | ① 精确高效 | 超长序列跨卡 | **不改变**（精确） | 多卡分块、环形传 K/V | 长上下文服务 |
| Longformer / BigBird | 2020 | ② 降复杂度 | 长序列 $O(n^2)$ | **改变**（稀疏近似） | 滑窗 + 全局 token | 长文档/基因 |
| Linformer / Performer | 2020 | ② 降复杂度 | 长序列 $O(n^2)$ | **改变**（低秩/核近似） | 低秩投影 / 核特征重排 | 学术/检索 |
| NSA 原生稀疏 | 2025 | ② 降复杂度 | 长序列近线性 | **改变**（稀疏近似） | 压缩 + 块选择 + 滑窗，原生训练 | **DeepSeek（研究原型）** |
| DSA | 2025 | ② 降复杂度 | 长序列稀疏读 | **改变**（token 级 top-k） | lightning indexer，落在 MLA 的 MQA 模式 | **DeepSeek-V3.2、GLM-5** |
| QSA | 2026 | ② 降复杂度 | 长序列稀疏读 | **改变**（micro-block top-k） | 轻量压缩索引器，与线性层 1:3 交错 | Qwen3.8-Flash-Next |
| CSA+HCA | 2026 | ② 降复杂度 | 1M 超长上下文 | **改变**（序列维压缩） | 两种压缩块交错 + on-disk KV | DeepSeek-V4-Flash |
| GDN/KDA | 2025–26 | ② 降复杂度 | KV 不随长度增长 | **改变**（固定状态替代 KV） | 门控差分递推，混合精确/稀疏层兜底 | Qwen3-Next/3.5/3.8-Flash-Next、GLM-5.3-Flash |
| MQA | 2019 | ③ 省 KV Cache | KV Cache 太大 | 不改变（结构共享） | 所有 Q 共享 1 组 K/V | PaLM / Falcon |
| GQA | 2023 | ③ 省 KV Cache | KV Cache 折中 | 不改变（结构共享） | Q 分组共享 K/V | **LLaMA/Qwen/GLM/DeepSeek/Mistral** |
| MLA | 2024 | ③ 省 KV Cache | KV Cache 压缩最强 | 不改变（低秩等价 + RoPE 解耦） | K/V 压成低秩潜变量缓存 | **DeepSeek-V2/V3/R1** |

**一句话选型/现状**：
- **底层加速**（任何模型都受益） → FlashAttention；**多卡超长序列** → Ring Attention；
- **长序列要近线性** → 2025 年的 NSA 原型已演进为 2026 年产品化的 token 级稀疏（**DSA/QSA**，KV 还在、只读 top-k）；
- **百万级上下文、固定 KV 预算** → 2026 前沿走**混合栈**：GDN/KDA 线性状态层（显存不随长度增长）打底，DSA/QSA 稀疏层与少量精确层兜底检索（Qwen3.8-Flash-Next、GLM-5.3-Flash、DeepSeek-V4-Flash）；
- **推理省显存/高吞吐** → GQA 是当前标配，追求极致压缩用 **MLA**（DeepSeek 路线）；
- ① 精确高效、③ 省 KV 都是**数学等价**优化，可自由叠加；② 是**近似**，用效果换长度。

**国产模型关注（截至 2026-10）**：DeepSeek 走出 MLA（V2/V3/R1）→ NSA 研究原型 → **DSA token 级稀疏（V3.2）→ CSA/HCA 强压缩（V4-Flash，1M 上下文）** 的完整路线；Qwen 从 GQA（Qwen2/2.5）演进到 **GDN 线性混合（Qwen3-Next、Qwen3.5）与 GDN+QSA（Qwen3.8-Flash-Next）**，并开源 FlashQLA kernel；GLM/智谱从 GQA（GLM-4）到 **MLA+DSA（GLM-5）、KDA 线性混合（GLM-5.3-Flash）**；Kimi 的长上下文工程沉淀为 KDA。国产模型在「省 KV → 稀疏读取 → 固定状态记忆」三代路线上都是主力贡献者。

## 自测（答案点击展开）

**Q1. 为什么说 FlashAttention 和 GQA 不冲突、可以同时用？它们优化的是同一个东西吗？**

<Expand title="查看答案">

不是同一个东西，且正交可叠加。
- **FlashAttention** 属于主线①：优化注意力**怎么算**（分块/IO 感知），**计算结果完全不变**，解决"算得慢、中间矩阵占显存"；
- **GQA** 属于主线③：优化**缓存/搬运多少 K/V**（多 Q 头共享），也是数学等价，解决"KV Cache 占显存、吞吐低"。

一个管「单次注意力计算的效率」，一个管「跨 token 缓存的 KV 大小」，作用层次不同，因此实际推理引擎（如 vLLM）里两者是一起开的。

</Expand>

**Q2. GQA 和 NSA 都能降低长序列成本，它们的本质区别是什么？哪个改变了注意力的计算结果？**

<Expand title="查看答案">

- **GQA** 是主线③（省 KV Cache）：通过让多个 Q 头共享 K/V 来**压缩缓存和搬移量**，注意力的数学结果与标准 MHA 等价（只是参数训练成共享形式），**不改变计算结果**；
- **NSA** 是主线②（降复杂度）：通过「压缩 + 块选择 + 滑窗」让每个 token **只关注一部分位置**，是**稀疏近似**，**改变了计算结果**（不再是完整 softmax 注意力），但长序列推理近线性、且原生训练保证效果。

一句话：GQA 省的是"缓存"，NSA 省的是"计算的 token 对数"；前者精确、后者近似。

</Expand>

**Q3. MLA 相比 GQA 在压缩 KV Cache 上更进一步，关键做法是什么？为什么还要搞"RoPE 解耦"？**

<Expand title="查看答案">

- **关键做法**：GQA 只是减少 K/V 的**头数**；MLA 干脆把 K、V 本身通过**下投影压成一个低维潜向量** $c_t=W^{DKV}h_t$（$d_c\ll d$），推理时**只缓存 $c_t$**，用到时再上投影 $k_t=W^{UK}c_t$、$v_t=W^{UV}c_t$ 恢复各头 K/V，因此缓存维度大幅降低（低秩压缩）。
- **为什么 RoPE 要解耦**：RoPE 是对 Q/K 按位置做旋转，旋转后的向量难以再被低秩压缩直接表示；如果把带 RoPE 的 K 也压进潜向量，会破坏压缩与位置信息。MLA 因此把 Q/K 拆成「内容部分」（走低秩压缩）和「位置部分」（小部分维度单独施加 RoPE 再拼接），既保住相对位置感知、又不牺牲 KV 压缩率。

</Expand>

**Q4（加分）. DSA 和 GDN 都在「省 KV」，它们的 KV 还逐 token 存在吗？为什么 GDN 必须和精确/稀疏层混合？**

<Expand title="查看答案">

- **DSA（DeepSeek Sparse Attention）仍逐 token 缓存 KV**（在 MLA 里是 576 维压缩潜变量），只是读取时用索引器做 token 级 top-k 选择（$k=2048$），从「全读」变成「挑着读」，属于稀疏近似；QSA 同理。
- **GDN/KDA 不存逐 token 的 K/V**，只维护一个与序列长度无关的固定大小状态矩阵，按门控差分规则递推，decode 时用 $q_t^\top S_t$ 读出。旧 token 会被衰减/覆盖、**无法精确定位任意历史位置**，所以必须周期性插入精确（全注意力/MLA）或稀疏（DSA/QSA）层兜底检索——这就是 2026 年模型普遍采用「线性状态层 + 稀疏/精确层」混合栈的原因。

</Expand>
