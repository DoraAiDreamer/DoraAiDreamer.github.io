一个 7B 模型用 FP16 跑要 ~14 GB 显存（几乎塞不进一张消费级显卡），量化到 INT4 只要 ~4 GB——这意味着原本要 A100 的模型，量化后一张游戏卡甚至手机都能跑。**量化（Quantization）是大模型落地最实用、性价比最高的技术之一**，也和本博客[推理加速实战](/inference/)里 vLLM 的显存/吞吐优化直接相关。这篇讲清楚：量化为什么有效、PTQ 与 QAT、GPTQ / AWQ / GGUF / FP8 的差异、以及到底该怎么选。

# 1. 为什么量化有效

## 1.1 数值格式：参数到底占多少空间

模型权重本质是一堆浮点数，不同数值格式的精度和体积差很多：

| 格式 | 位数 | 每参数字节 | 数值范围 | 典型用途 |
| --- | --- | --- | --- | --- |
| FP32 | 32 bit | 4 B | ±3.4×10³⁸ | 传统训练 |
| FP16 | 16 bit | 2 B | ±6.5×10⁴ | 混合精度训练 / 推理 |
| BF16 | 16 bit | 2 B | ±3.4×10³⁸ | 大模型训练首选 |
| INT8 | 8 bit | 1 B | −128–127 | 量化推理 |
| INT4 | 4 bit | 0.5 B | −8–7 | 激进量化推理 |

**BF16 vs FP16**：FP16 有 10 位尾数 + 5 位指数，精度高但范围小（最大才 6.5 万）；BF16 有 8 位指数 + 7 位尾数，**范围和 FP32 一样大**、精度低些。大模型训练梯度动态范围极大，「溢出」比「精度低」更致命，所以训练普遍用 BF16。

## 1.2 一个 7B 模型在不同精度下的显存

以 Qwen2.5-7B（约 72 亿参数）为例：

| 精度 | 权重存储 | 实际推理显存（含 KV Cache 等） | 相对 FP32 |
| --- | --- | --- | --- |
| FP32 | ~28 GB | ~32 GB | 1× |
| FP16 / BF16 | ~14 GB | ~18 GB | ≈ 0.56× |
| INT8 | ~7 GB | ~10 GB | ≈ 0.31× |
| INT4（GPTQ/AWQ） | ~3.5 GB | ~6 GB | ≈ 0.19× |
| Q4_K_M（GGUF） | ~4.1 GB | ~6.5 GB（CPU 也可） | ≈ 0.2× |

推理显存比纯权重多出来的部分，主要是 **KV Cache、激活值和框架开销**——这也是为什么上下文越长、并发越高，显存涨得越快（见[推理加速实战](/inference/)）。

## 1.3 量化的核心数学

**量化的本质：用更少的 bit、也就是更少的离散取值，去近似原来的高精度（近乎连续）数值。** 最典型的是「浮点→整数」的定点量化——把浮点数映射到一排**等距的整数台阶**上（像吸附到最近的格点）；此外还有「高精度浮点→低位宽浮点」（FP8/FP4，吸附到浮点自己的非均匀网格）。下面先用最直观、也最常见的**对称定点量化**（权重量化的主流做法）逐步讲清整数台阶这一种，浮点量化见 3.4 节。

**第一步：确定范围。** 假设这一组权重的浮点值落在 $[-\alpha,\ \alpha]$（$\alpha$ 取这组数里绝对值最大的那个，再留点余量）。

**第二步：算 scale（台阶宽度）。** $n$ 位整数一共能表示 $2^{n}$ 个数，对称情形下正负各占一半（$-2^{n-1}\sim 2^{n-1}-1$）。把浮点区间 $[-\alpha,\alpha]$ 均分给这些整数，每一小格代表多宽的浮点范围，就是 **scale**：

$$
s=\frac{\alpha}{2^{n-1}}
$$

直观上 $s$ 就是「**一个整数台阶 = 多少浮点数**」。以 INT4（$n=4$）为例，整数范围是 $-8\sim 7$，共 16 个台阶。

**第三步：量化（float → int）。** 把浮点数除以台阶宽度、四舍五入到最近的整数：

$$
q=\mathrm{round}\!\left(\frac{w}{s}\right)
$$

**第四步：反量化（int → float，推理时还原）。** 整数本身没有量纲，乘回 scale 就还原成浮点：

$$
\hat{w}=s\cdot q\approx w
$$

因为 $\mathrm{round}$ 会丢掉「不到半个台阶」的零头，$\hat{w}$ 和原始 $w$ 之间差了最多 $\pm s/2$——这就是**量化误差**。台阶越密（$s$ 越小 / 比特越多），误差越小。

<QuantAxisFigure />

**一个具体数字例子。** 假设这组权重的最大绝对值 $\alpha=0.5$，用 INT4（$2^{n-1}=8$）：

$$
s=\frac{0.5}{8}=0.0625
$$

- 某个真实权重 $w=0.137$：量化 $q=\mathrm{round}(0.137/0.0625)=\mathrm{round}(2.19)=2$；
- 反量化 $\hat{w}=0.0625\times2=0.125$，和真实值 0.137 只差 0.012；
- 另一个权重 $w=-0.47$：$q=\mathrm{round}(-0.47/0.0625)=\mathrm{round}(-7.52)=-8$，$\hat{w}=0.0625\times(-8)=-0.5$。

一个权重从「4 字节浮点」变成「半个字节整数」，只需要额外存一个（或每组一个）几字节的 $s$——权重体积压到原来的约四分之一，这就是显存量能降到约 1/4 的原因。

**非对称量化与 zero-point。** 如果分布不是正负对称（比如激活值几乎全为正），纯对称映射会浪费一半整数区间。这时引入一个 **zero-point** $z$（整数 0 所对应的位置），把映射平移：

$$
q=\mathrm{round}\!\left(\frac{w}{s}\right)+z,\qquad \hat{w}=s\,(q-z)
$$

- **对称量化**（symmetric）：$z=0$，只有一个 scale，计算快、kernel 简单，**权重**量化常用；
- **非对称量化**（asymmetric）：带 $z$，能贴合偏移的分布，**激活**量化常用。

> **量化不一定是「浮点→整数」。** 上面的 round + scale 是**定点（整数）量化**（INT8/INT4，如 GPTQ/AWQ/GGUF），压缩比高但要算 scale/zero-point。还有一类是**高精度浮点 → 低位宽浮点**：保留浮点数的「指数+尾数」结构，只是位宽更短，典型就是 **FP8（E4M3）**（见 3.4 节，H100 原生）、以及更新的 FP4/NVFP4。浮点量化动态范围大、对激活里的离群值更鲁棒、基本不用复杂校准，硬件支持时又快又稳；整数量化压缩比更高、不挑硬件。本文多数公式以整数量化为例。

信息必然丢失——0–1 的浮点数 FP16 能用上千个值表示，INT4 只有 16 个台阶。但实际精度损失小得惊人，原因有三：

1. **权重分布有规律**：大部分权重集中在 0 附近、极端值少，0 附近台阶"利用率"最高；
2. **模型本身有冗余**：很多参数微小变化对输出影响很小；
3. **分组量化**（group quantization）：不整张矩阵共用一组 $s,z$，而是每 128 个元素用一组 scale/zero-point——不同小组各自适应自己的数值范围，误差大幅降低（代价是多存一些 scale）。

> 实测 Qwen2.5-7B 用 INT4（AWQ）量化后，MMLU/GSM8K 等基准掉点通常 **&lt; 1–2%**，而显存省了约 75%。这个 tradeoff 对绝大多数场景都划算。

# 2. PTQ vs QAT：两条技术路线

## 2.1 PTQ（Post-Training Quantization，训练后量化）

训练完之后再量化，**不用重新训练**，只需一小批 **校准数据**（calibration data，通常几百条文本）统计权重/激活分布：

1. 加载 FP16 模型 → 2. 用校准数据跑前向、收集各层统计 → 3. 计算 scale / zero-point → 4. 转低精度 → 5. 保存。

- ✅ 简单快速（几十分钟到几小时）、不需要训练集群；GPTQ / AWQ / GGUF 都属此类
- ❌ INT2 等极端比特下损失明显

## 2.2 QAT（Quantization-Aware Training，量化感知训练）

训练时就在前向插入 **fake quantization**（伪量化） 节点——前向做「量化→反量化」模拟低精度误差（权重仍 FP32），让模型**学着适应量化噪声**；反向用 **STE**（Straight-Through Estimator，直通估计器） 绕过量化函数的不可导问题（把梯度原样直通）。

- ✅ 精度损失最小，INT4/INT2 下优势明显
- ❌ 要完整训练流程、要数据、成本高

**实践结论**（2025/2026）：PTQ 是绝对主流，AWQ INT4 的效果已经足够好；除非做 INT2 或精度要求极端，直接 PTQ。

# 3. 主流量化方法详解

## 3.1 GPTQ：基于 Hessian 的逐层量化

GPTQ（2022）是第一个让 **INT4 大模型真正实用**的方法。核心思路：

1. **逐层量化**，量化一层时用 Hessian 矩阵衡量每个权重对输出的影响；
2. **最优顺序 + 误差补偿**：先量化对输出影响最小的权重，再调整其余权重补偿误差；
3. **分组量化**：每 128 个权重共享一组量化参数。

**Hessian 为什么出现**：要最小化「量化前后该层输出的差异」$\lVert XW - XW'\rVert^2$，对权重做二阶泰勒展开得到 $\mathbf{H}=X^{\top}X$（$X$ 是校准前向得到的激活）。H 对角线大的权重量化敏感度高、要小心；$H^{-1}$ 用来算「量化掉某个权重后，剩下的往哪偏多少能摊平误差」。Hessian 是校准时**现算**的，所以 GPTQ 必须有校准过程。

**工具链**：最早的 AutoGPTQ 已归档（2025-04），继任者是 [GPTQModel](https://github.com/ModelCloud/GPTQModel)（多算法：GPTQ/AWQ/GGUF/FP8）。

```python
from gptqmodel import GPTQModel, QuantizeConfig
from transformers import AutoTokenizer
from datasets import load_dataset

model_id = "Qwen/Qwen2.5-7B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_id)

# 校准数据：通用场景用 C4（清洗网页语料）128–1024 条；垂直领域可换领域文本
calib = [
    tokenizer(ex["text"])
    for ex in load_dataset("allenai/c4",
            data_files="en/c4-train.00001-of-01024.json.gz",
            split="train").select(range(1024))
]

quant_config = QuantizeConfig(bits=4, group_size=128)  # INT4，每 128 权重一组
model = GPTQModel.load(model_id, quant_config)
model.quantize(calib)
model.save("Qwen2.5-7B-Instruct-GPTQ-Int4")
```

## 3.2 AWQ：激活感知的权重量化

AWQ（2023，MLSys 2024 最佳论文）思路更优雅，是**当前生产环境 INT4 推理的事实标准**。

**核心洞察**：不是所有权重都一样重要——**有 1% 左右的「显著权重通道」，其对应的激活幅度特别大**，这些通道的量化误差会被大激活放大、对输出影响最大。

**做法**：校准统计各通道激活幅度 → 找出重要通道 → 量化前**先放大这些通道的权重**（per-channel scaling），让它们获得更高有效精度；同时**缩小对应激活**保持数学等价（权重乘 $s$、激活除以 $s$，两者相乘结果不变）。

<AwqFigure />

*图：直接量化时，少数「对应大激活的重要通道」被粗糙的 INT4 台阶压坏、误差被放大；AWQ 在量化前先把这些权重放大（激活同步缩小保持数学等价），使它们落在更密的量化台阶上，量化后更准，而普通通道几乎不动。*

**为什么通常比 GPTQ 好**：不反复补偿权重（计算快 2–3 倍、误差不跨层累积），只做简单 scaling 就保护了关键通道，同等比特下精度更高、更稳定。

**工具链**：AutoAWQ 已归档，官方推荐 [vllm-project/llm-compressor](https://github.com/vllm-project/llm-compressor)（vLLM 团队统一量化工具，支持 AWQ/GPTQ/FP8/INT8）；GPTQModel 也支持 AWQ。vLLM / SGLang / TensorRT-LLM 都内置了优化的 AWQ kernel。

## 3.3 GGUF：llama.cpp 生态，面向 CPU / 本地

GGUF 走完全不同的路线：**面向 CPU 和 CPU+GPU 混合推理**（llama.cpp / Ollama），不依赖 CUDA kernel。

量化类型命名有规律：

- `Q` + 数字 = 比特数（Q4=4bit，Q5=5bit…）
- `K` = K-quant（非均匀量化：对注意力/FFN 关键层用更高比特保护质量）
- `_S / _M / _L` = Small / Medium / Large（L 保留更多高精度层）

| 类型 | 有效 bpw | 7B 大小 | 质量 | 建议 |
| --- | --- | --- | --- | --- |
| Q2_K | 2.6 | ~2.8 GB | 明显降质 | 不推荐 |
| Q3_K_M | 3.3 | ~3.3 GB | 可用、有损 | 显存极端受限 |
| **Q4_K_M** | 4.5 | ~4.1 GB | 好 | **性价比最高** |
| Q5_K_M | 5.3 | ~4.8 GB | 很好 | 生产推荐 |
| Q6_K | 6.6 | ~5.5 GB | 接近 FP16 | 追求质量 |
| Q8_0 | 8.0 | ~7.0 GB | 几乎无损 | RAM 充足 |

> bpw（bits per weight）= 含 scale/zero-point 开销后的平均每权重比特；K-quant 对不同层用不同精度，所以不是整数。

**适用**：本地/边缘部署、没有 GPU、macOS（Metal 加速）、开发者电脑上快速跑模型。

```bash
# llama.cpp：先把 HF 模型转成 GGUF（fp16），再量化
python convert_hf_to_gguf.py Qwen2.5-7B-Instruct --outfile qwen2.5-7b-f16.gguf
llama-quantize qwen2.5-7b-f16.gguf qwen2.5-7b-q4_k_m.gguf Q4_K_M
# 之后可直接用 llama-cli 或 Ollama 加载
```

## 3.4 FP8：Hopper 硬件原生格式

FP8 不是软件近似，而是 **H100/H200/Blackwell（B200）Tensor Core 硬件原生支持的 8-bit 浮点**。两种变体：**E4M3**（4 指数+3 尾数，精度优先，常用于存权重）和 E5M2（范围优先）。

| 对比 | FP8 | INT4 |
| --- | --- | --- |
| 精度 | 接近 BF16，掉点通常 &lt;0.5% | 掉点 1–2% |
| 速度（H100 GEMM） | BF16 的 **2 倍** | 更快但需专门 kernel |
| 显存 | 1 B/参数（比 BF16 减半） | 0.5 B（压缩比更高） |
| 硬件 | **必须 Hopper 及以上**（A100 不支持） | 各代 GPU 均可 |

```bash
vllm serve neuralmagic/Qwen2-7B-Instruct-FP8 \
    --quantization fp8 \
    --kv-cache-dtype fp8      # KV Cache 也可量到 FP8，进一步省显存
```

有 H100 集群、追求精度/速度平衡 → FP8 首选；还是 A100 → 走 AWQ INT4。

## 3.5 W4A16 / W8A8：权重和激活分别量到多少位

前面 GPTQ/AWQ/FP8 常带一串「W?A?」记号——**W 是权重（Weight）、A 是激活（Activation）**，数字是各自的位宽。它描述的是「一次前向里，权重存多少位、激活算多少位」，和用哪种算法是**正交**的两个维度：

| 记号 | 权重 | 激活 | 说明 | 典型 |
| --- | --- | --- | --- | --- |
| **W16A16** | 16 bit | 16 bit | 不量化（BF16/FP16 原生） | 原始模型 |
| **W8A16** | 8 bit | 16 bit | 只压权重，激活不量 | 早期权重量化 |
| **W4A16** | 4 bit | 16 bit | **当前最主流**：权重压到 INT4，激活保持 FP16 | GPTQ / AWQ / GGUF Q4 |
| **W8A8** | 8 bit | 8 bit | 权重和激活都压到 8 位，整数算得快、省显存 | SmoothQuant / FP8 推理 |

**为什么权重敢量到 4 位、激活却常留 16 位？** 权重训练完就固定，可以精心校准（GPTQ/AWQ）把误差摊平；激活是实时算出的，且有少量**极端离群值（outlier）**，幅度能比普通值大成百上千倍，一旦量化误差被放大会显著影响结果——所以激活更难量，通常更保守（用 16/8 位，或用浮点 FP8 而非整数）。

<WaFigure />

*图：权重数值集中、训练后不变、可离线反复校准，所以能放心压到 INT4；激活每个 token 实时生成，且有少数幅度大成百上千倍的离群值，量化失真会被这些大值放大并污染整层，所以激活更保守（留 16 位、或仅到 8 位，W8A8 还要先用 SmoothQuant 把离群值平滑掉）。*

**一个直观例子。** 假设某层激活里 99% 的值都在 $-1$ 到 $1$ 之间，但有一个通道的某个 token 出现了约 60 的离群值。若直接 INT4 量化，台阶必须先覆盖到 60，那么原本落在 $[-1,1]$ 之间的 99% 的值，会被挤到同几个台阶上、彼此完全分不开；权重则不同——它的分布训练后平滑集中，校准时可以给不同小组各配一个合适的小台阶，每个重要权重都分得开。这就是 W4A16 成为主流、而激活要量到 8 位通常得先平滑离群值的根本原因。

- **W4A16**：压缩比最高（权重是显存档）、效果好、几乎所有推理框架都支持，是部署默认选择；
- **W8A8**：激活也 8 位后，矩阵乘可以用 **INT8/FP8 GEMM** 直接在低精度上算，**速度更快**（FP8 在 H100 上吞吐翻倍），但需要硬件支持、且要靠 SmoothQuant 等手段处理激活离群值。

这也把前面的方法串起来了：**GPTQ/AWQ 主要做 W4A16**（专注把权重压到 INT4），**SmoothQuant/FP8 走 W8A8**（权重激活都 8 位、追求速度）。

## 3.6 国产硬件视角：华为昇腾 NPU 的量化

量化用哪种格式，很大程度**取决于硬件擅长什么**。英伟达 H100 靠原生 FP8 拿翻倍吞吐，华为昇腾（Ascend）NPU 走的是另一条路：

- **达芬奇架构（Da Vinci）的 Cube 计算单元对 INT8 有原生高算力**——昇腾上的主力低精度格式是 **W8A8（权重+激活都量化到 INT8）**，INT8 矩阵乘在 Cube 单元上吞吐远高于 FP16，精度损失也可控。这条思路正是前面讲的 **SmoothQuant W8A8**：先把激活里的离群值「平滑」给权重，再整网跑 INT8。
- **常用非对称量化**（带 zero-point），配合 per-channel / per-layer 的 scale。
- **工具链**：用 **AMCT（Ascend Model Compression Toolkit，昇腾模型压缩工具）** 做 PTQ 校准量化——一小批校准数据跑前向、统计权重/激活分布、生成 scale；再经 **ATC** 把模型转成昇腾 **OM** 格式，运行在 **CANN** 平台。大模型推理则用 **MindIE**（支持 INT8 W8A8，也在逐步支持 W4A16 等权重量化）。
- **和英伟达的对照**：

| 硬件 | 主力低精度格式 | 说明 |
| --- | --- | --- |
| NVIDIA H100/H200/Blackwell | **FP8**（E4M3，浮点 8 位） | Tensor Core 原生支持，掉点极小、吞吐 2× |
| 华为昇腾 910 系列（Atlas） | **INT8 W8A8**（整数 8 位） | Cube 单元 INT8 算力强，主流走全整数量化 |
| CPU / 消费卡 / 本地 | **INT4 权重**（W4A16、GGUF） | 不依赖特殊算力单元，兼容最广 |

一句话：**量化选型跟着硬件走——英伟达新卡用 FP8、昇腾 NPU 用 INT8 W8A8（配 AMCT，思路同 SmoothQuant）、CPU/本地用 GGUF INT4**。目标一致：用低精度高吞吐的 GEMM 跑更大更快的模型。

## 3.7 其它常听到的名字

- **bitsandbytes**：HuggingFace 原生的开箱即用量化（`load_in_4bit=True` 一行启用，NF4/FP4），**加载时即时量化**，是 QLoRA 的配套库。适合快速实验/微调，缺点是不生成可分发的量化文件、推理不如 AWQ kernel 快。
- **SmoothQuant**：针对 INT8 中**激活离群值**（outlier）撑爆量化范围的问题，量化前把激活的尺度按 channel「平滑」转移到权重上（W8A8 = 权重激活都 8-bit）。已被吸收进 llm-compressor，是 Hopper 之前 INT8 推理的常用方案。

## 3.8 方法对比与选型

| 维度 | GPTQ | AWQ | GGUF | FP8 |
| --- | --- | --- | --- | --- |
| 推理设备 | GPU | GPU | CPU / CPU+GPU | GPU（H100+） |
| 典型精度 | INT4/INT8 | INT4 | Q2~Q8 多档 | FP8 (E4M3) |
| 量化速度（7B） | 慢（1–4h） | 快（20–40min） | 几分钟 | 10–30min |
| 推理速度 | 快 | 快 | 较慢 | 极快 |
| CPU 支持 | ✗ | ✗ | ✓ | ✗ |
| 生态 | vLLM/SGLang/TRT-LLM | vLLM/SGLang/TRT-LLM | llama.cpp/Ollama | vLLM/SGLang/TRT-LLM |
| 推荐场景 | GPU 服务端 | **GPU 服务端首选** | 本地/边缘/CPU | H100+ 精度敏感 |

**一句话选型**：
- 有 **H100/H200**、要精度和速度 → **FP8**
- **华为昇腾 NPU（Atlas/910）** → **INT8 W8A8**（AMCT 校准 + MindIE 推理，思路同 SmoothQuant）
- A100 / 消费级 GPU、服务端部署 → **AWQ INT4**（GPTQ 作为备选）
- 在 **Mac/CPU/本地** 跑、用 Ollama/llama.cpp → **GGUF Q4_K_M / Q5_K_M**
- 只是做 QLoRA 微调实验 → **bitsandbytes NF4**

# 4. 几个容易踩的点

<Expand title="扩展：量化的常见误区与实践细节">

**「量化」到底量的是什么？权重 vs KV Cache vs 激活。** 量化是「高精度数 → 低精度数」的通用技术，可作用在不同对象上：

| 对象 | 何时确定 | 特点 | 典型方案 |
| --- | --- | --- | --- |
| **权重** | 训练完即固定 | 占显存固定、与上下文长度无关；可离线提前量化、保存分发 | GPTQ / AWQ / GGUF（W4A16） |
| **KV Cache** | 推理时逐请求动态生成 | 随上下文长度/并发膨胀，长文本时会**超过权重**成为瓶颈；只能运行时量化 | `--kv-cache-dtype fp8` / INT8 KV |
| **激活** | 推理中间值 | 临时、随 batch 变；有少量极端离群值、最难量化 | SmoothQuant / W8A8 / FP8 |

所以：
- 平时说的「下了一个 AWQ/INT4 量化模型」指的是**权重量化**（离线做好、省固定显存）；
- 「长上下文/高并发爆显存」时开的 FP8 KV Cache 是 **KV Cache 量化**（运行时、省动态显存）。

**两者是独立开关，不是二选一。** 权重量化只改变「权重」这一块，KV Cache 是推理时另外生成、单独分配的张量，**默认仍是 FP16，与权重是否 INT4 无关**。以 7B 长上下文服务为例：权重 INT4 约占 4 GB（固定），而 KV Cache 在长文本/高并发下可涨到 10–20 GB——权重压得再狠也压不到 KV。因此生产部署常把两者都开：**INT4 权重 + FP8 KV Cache**，固定显存（权重）和动态显存（缓存）一起压。KV Cache 用 FP8 而非 INT4，是因为它属于激活、有离群值，FP8（浮点）更稳、精度损失极小。

**注意：KV Cache 精度和 W?A? 里的「A」也是两回事。** W4A16 / W8A16 说的「激活」指参与矩阵乘（GEMM）运算的张量——计算时用 16 位；KV Cache 是其中需要**持续存储、跨步复用**的历史 K/V，它存多高精度可以**单独设置**。所以「W4A16 计算激活 16 位 + KV Cache 用 FP8/INT8 存储」完全可行，也是 vLLM 常见组合：缓存以 8 位存（省显存），用到时临时转回 FP16 参与注意力计算，算完新 K/V 再量化回 8 位存好。

（W4A16 / W8A8 的位宽取舍与 GPTQ/AWQ/FP8/SmoothQuant 的对应关系，见正文 3.5 节。）

- **group_size 的取舍**：越小（如 32）精度越高但 scale 元数据越多、kernel 越慢；**128 是社区默认折中**。
- **校准数据要贴近业务**：通用模型用 C4/百科；若你的服务主要是中文/代码/医疗，混入领域文本能明显降低量化损失。
- **量化 ≠ 蒸馏/剪枝**：量化只改数值精度，不改结构；剪枝是去掉权重、蒸馏是用大模型教小模型，三者可叠加。
- **KV Cache 也能量化**：`--kv-cache-dtype fp8` 能显著降低长上下文/高并发的显存，代价是极小的精度损失。
- **下载量化模型**：HuggingFace 上大量现成 GPTQ/AWQ/GGUF 量化版（如 `Qwen2.5-7B-Instruct-AWQ`），多数情况直接下载即可，不必自己量化。
