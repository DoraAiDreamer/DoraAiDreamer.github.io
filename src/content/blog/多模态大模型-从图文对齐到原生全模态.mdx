让大模型能看、能听、还能说，是这两年架构演进的主线。理解多模态（multimodal）有一个特别清晰的脉络——**从「拼接式」到「原生多模态」**：早期是给一个现成的文本大模型"外挂"一个视觉模块，现在则是从预训练起就让文本、图像、语音在同一个骨干里端到端训练。这篇讲清多模态要解决的核心问题、桥接机制、训练范式，并用三个国产原生多模态代表覆盖"理解、行动、生成"三个方向：**Qwen3.5-Omni**（全模态理解 + 语音流式输出）、**Kimi K2.5**（视觉原生 + 智能体）、以及 **MiniMax H3**（音视频联合生成）。

## 1. 多模态到底难在哪

文本在模型里是离散的 token id；但图像是像素网格、语音是连续声波、视频是一连串帧——这些都是**连续、高维**的信号。大语言模型只"懂"自己表征空间里的向量，多模态要解决的核心问题就是：

- 怎么把图像/音频编码成**模型能理解的向量**（编码器）；
- 怎么让这些向量和**语言向量对齐到同一个语义空间**（对齐/桥接）；
- 什么时候、用什么方式把非语言信息**注入** LLM（融合时机）。

最后这个"什么时候融合"，正是拼接式和原生多模态的分水岭。

## 2. 输入侧：视觉与听觉编码器

多模态模型先用一个专门的编码器把原始信号变成特征：

- **视觉**：早期用 CNN（ResNet），现在主流是 **ViT**（Vision Transformer）——把图像切成小块（patch），每个 patch 线性投影成一个向量，当作"视觉 token"送进 Transformer。
- **图文对齐的基石是 CLIP**（2021）：用**对比学习**预训练——配对的"图-文"表示拉近、不配对的推远，让图像和文本进入同一个语义空间。后来的 EVA-CLIP、SigLIP2 都是这个思路的增强。
- **音频**：用类似的语音编码器（如 Whisper 风格、或从零训练的音频 encoder）把声波/声学帧变成特征，通常按时间片（如每 160ms 一帧）输出。
- **视频**：本质是"有时间顺序的一组帧"，常复用视觉编码器逐帧/抽帧处理，再额外建模时序。

<Expand title="扩展：ViT 与 CLIP 对比学习的数学直觉">

ViT 把图像分成 $P\times P$ 个 patch，拉直后线性投影：$z_0 = [x_p^1E, x_p^2E, \dots]$，再和文本 token 一样过 Transformer。

CLIP 训练时，对一个 batch 里 $N$ 对 (图, 文)，算图文相似度矩阵 $S=I\cdot T^\top$，用 InfoNCE 对比损失：让对角线上"正确配对"的相似度最高、非配对最低，从而把两模态拉到同一空间。这让编码器天然产出"语义对齐"的视觉特征。

</Expand>

## 3. 拼接式模型：视觉怎么"接"进 LLM

有了视觉特征，还需要一个**桥接模块**（bridge / projector / connector）把它变成 LLM 能接收的嵌入。这是早期多模态模型（BLIP-2、LLaVA、MiniGPT-4）的核心，也是"拼接式"的标志：**LLM 本身冻结、只加一个轻量桥**。

<MmBridgeFigure />

*图 1：三种典型桥接机制——MLP 投影（LLaVA）、Q-Former（BLIP-2）、Perceiver Resampler（Flamingo）。它们都把视觉特征"翻译"成语言空间的 token，再喂给冻结的 LLM。*

**三种主流桥接：**

1. **线性/MLP 投影**（LLaVA 系列）：最简单——一个线性层（LLaVA 一代）或两层 MLP（LLaVA-1.5 起）直接把视觉特征映射到 LLM 的词嵌入维度。结构简单、效果好，成为开源范式标杆。
2. **Q-Former**（BLIP-2，2023）：用一小撮**可学习的 query**，通过交叉注意力从图像编码器的输出里"查询/抽取"关键信息，再交给 LLM。好处是用很少的可训练参数就把视觉桥接好（冻结图像模型和 LLM 两边）。
3. **Perceiver Resampler**（Flamingo，2022）：把数量不定的视觉特征**重采样成固定数量**的 token（perceiver 风格），再用交叉注意力注入；对变长图像/视频友好。

**为什么叫"拼接式"**：视觉信息是在 LLM 的**输入端末尾才拼接到语言序列上**（late fusion），LLM 的权重冻结、不为视觉做深层调整——像给一个现成的语言大脑"装了个外挂眼睛"。

## 4. 拼接式怎么训练：两阶段

<MmTrainFigure />

*图 2：拼接式模型两阶段训练——阶段一冻结编码器和 LLM、只训桥接层做对齐；阶段二放开 LLM，用视觉指令数据微调。虚线框表示冻结。*

<Expand title="扩展：训练流水线细节">

**阶段 1：对齐预训练**（alignment pretraining）：冻结图像编码器和 LLM，**只训练桥接层**（投影/Q-Former），用大量图文对（image-text pairs）让视觉嵌入对齐到语言空间——目标是让模型"看懂图在说什么"。

**阶段 2：视觉指令微调**（visual instruction tuning）：解冻部分/全部 LLM，用"图 + 指令 → 回答"的多模态对话数据（很多由 GPT 生成）微调，让模型学会按指令做视觉问答。LLaVA 验证了这套流程的强大。

冻结策略可以是完全冻结（省算力）、LoRA 微调、或全参微调。

</Expand>

- **阶段一**只训桥（对齐），**阶段二**再放开 LLM（学会对话）。成本低、能复用成熟 LLM，这正是拼接式 2023 年快速流行的原因。

## 5. 从拼接式走向原生多模态

拼接式简单有效，但有个上限：视觉只在末端注入，LLM 的深层语义推理没有真正"看"到图，跨模态交互较浅。**原生多模态**（native multimodal） 换了思路。

<MmNativeFigure />

*图 3：拼接式（上）是冻结的纯文本 LLM + 外挂桥，late fusion；原生多模态（下）从预训练起就让文本、图像/视频、语音 token 在同一个骨干的所有层里混排（early fusion），端到端训练。*

| 维度 | 拼接式 | 原生多模态 |
| --- | --- | --- |
| 训练方式 | LLM 冻结、只训桥/轻量微调 | 多模态数据**端到端预训练** |
| 融合时机 | 晚期融合（late fusion），视觉拼在输入 | **早期融合**（early fusion），浅层就交互 |
| 权重共享 | 文本 LLM 与视觉相对独立 | 文本/视觉/语音共享同一套骨干权重 |
| 输入/输出 | 主要"看图/听"输入，输出多为文本 | 可输入**且可输出**（能听能说、可生成） |
| 优势 | 复用现成 LLM、成本低、上手快 | 跨模态推理、时序理解、生成能力更强 |
| 代表 | BLIP-2、LLaVA、MiniGPT-4 | **Qwen-VL 系列、Gemini、Gemma3、Qwen3.5-Omni、Kimi K2.5** |

Kimi K2.5 的技术报告把这一点说得很直接：传统方法"在后期才把视觉 token 加入文本骨干"，而它在**整个训练过程中以恒定比例混合文本与视觉 token**（早期视觉融合），让两种模态在深层相互增强。

## 6. 多模态的关键能力

多模态能力可以分成**理解**（输入）和**生成**（输出）两类：

**理解侧：**
- **高分辨率 / 动态分辨率**：图像有大有小，早期固定 token 数会丢细节。做法是动态分块（tiling / any resolution / NaViT 打包），把高分辨率图切成多块分别编码。
- **视觉定位 Grounding**：不仅说出图里有什么，还能给出坐标（检测、分割、"指一下杯子在哪"）。
- **OCR / 文档理解**：读表格、公式、截图文字。
- **视频时序理解**：跨多帧的动作、因果、时间对齐。
- **语音理解**：语音识别、情感/意图。

**生成侧：**
- **文本回答**（视觉问答）；
- **语音合成 / 流式说话**（Qwen3.5-Omni）；
- **文生图 / 文生视频**——即多模态的"图像/视频生成"（如 MiniMax H3 用扩散 DiT 直接生成带声音的视频）。能生成图像/视频也是多模态，只是它走的是扩散去噪路线，而不是自回归吐 token（第 9 节展开）。

这些能力背后都在解决"视觉/音频 token 太多、太长"的效率问题——和本博客讲过的 KV Cache、注意力优化直接相关。

## 7. 重点案例 ①：Qwen3.5-Omni（全模态，能听能说）

Qwen3.5-Omni 是阿里 Qwen-Omni 系列的旗舰，定位**原生全模态**（omni-modal）：能同时接收文本、图像、视频、语音，并能输出文本和**流式语音**。据公开技术报告（[arXiv 2604.15804](https://arxiv.org/pdf/2604.15804v1)，2026），它是数百亿级参数、256K 上下文，训练用了超过 **1 亿小时**音视频内容。

<OmniFigure />

*图 4：Qwen3.5-Omni 的 Thinker-Talker 架构（示意）。视觉/音频/文本经编码器进入 Thinker 统一理解，Talker 负责流式语音输出。*

**架构：升级版 Thinker-Talker。** 模型分两个角色：

- **Thinker**（思考者）：一个 **Hybrid MoE Transformer**，统一理解文本、视觉、音频并产生决策；
- **Talker**（表达者）：另一个 Hybrid MoE，负责生成语音 token（配合 MTP 多 token 预测、Code2wav 卷积把声学码本重建成波形）；
- 编码器：视觉用 **SigLIP2**（图像+视频混合训练、分块输出），音频用从零训练的 **AuT**（约 160ms/帧）。

**为什么要拆成 Thinker 和 Talker 两个模型？** 全模态要同时做"多模态理解"和"流式语音合成"两件事：前者需要很强的推理能力、节奏慢；后者要求**低延迟、稳定地逐帧产出语音**。合成在一个模型里会互相拖累（语音生成对实时性的要求会限制理解模块）。拆成两个角色后：Thinker 负责"听懂/想清楚"，Talker 专职"把要说的内容变成声学码"，各自选用合适的结构与精度，Talker 还能流式启动、不必等整句想完。

- **Thinker**（思考者）：一个 **Hybrid MoE Transformer**——混合专家（FFN 层稀疏激活，省计算）+ 混合注意力（标准 softmax 注意力与 Gated DeltaNet 混用）。它统一编码文本、视觉、音频，输出高层的"要表达的语义/决策"。
- **Talker**（表达者）：另一个 Hybrid MoE，负责把语义转成**离散声学码本**（speech codecs token），并通过 **MTP**（多 token 预测，一次预测多个码本 token） 和 **Code2wav**（因果卷积网络） 把码本重建成连续语音波形——避免了传统 TTS 那种"先整句再出声"的高延迟。
- 编码器：视觉用 **SigLIP2**（图像+视频混合训练、按时间分块输出）；音频用从零训练的 **AuT**（约 **160ms/帧**，直接从长音频学习声学+语义表示，而不是分成独立的 ASR/TTS 两块）。

它和本博客前面系列文章高度联动，几个关键机制展开如下：

1. **Gated DeltaNet（GDN）与混合注意力**：音视频输入动辄上万 token，若全用标准 softmax 注意力，KV-Cache 和 $O(n^2)$ 计算都扛不住。Thinker/Talker 把**部分层换成 Gated DeltaNet**（一种门控线性注意力，带固定大小的状态、KV 不随序列增长），其余层保留精确注意力做检索——正是[线性注意力回归](/blog/线性注意力为何回归-gated-deltanet/)里"线性层压长程、注意力层做精确定位、两者混用"的生产落地；FFN 层再用 [MoE 稀疏激活](/blog/moe混合专家模型-以deepseek为例/)省计算。三者叠加，才让超长音视频的全模态模型跑得动。
2. **ARIA（Adaptive Rate Interleave Alignment，自适应交错对齐）——最核心的生成端创新。** 文本和语音的"产出速率"天然不匹配：一个文字 token 可能对应几个到几十个声学帧，而且这个比例随内容（数字、标点、停顿）变化。早期方案让文本流和语音流并行/双通道，一旦错位就会出现**漏字、吞音、数字读错、流式抖动**。ARIA 的做法是把两路**统一成一条单通道交错流**：在同一个序列里，文本 token 和它对应的语音单元按"谁准备好谁跟上"的方式动态插入、自适应对齐，由模型自己学两种模态之间的速率映射，保证"说到哪个词、声音就到哪个词"。
3. **时间对齐：显式时间戳替代绝对位置 ID**：长视频里"第几秒说的、画面在第几帧"需要统一时间坐标。Qwen3.5-Omni 不再给每个 token 编一套绝对时间位置（旧的 TMRoPE 方案），而是直接在视频/音频块前**注入文本形式的时间戳**（音频约每 160ms 一个、视频按秒），让模型像读文字一样读时间——跨模态（尤其长视频）的"谁先谁后、是否同时"对齐更稳。
4. **分块预填充（Chunked Prefilling）与低首包延迟**：音视频编码器沿时间分块、边编码边输出特征，而不是等整段音视频处理完再一次性喂给模型，因此响应的**首包延迟**（time-to-first-token）大幅降低——音频输入首包可低至约 **235ms**、视频约 426ms（Flash 版），对实时对话很关键。

<Expand title="扩展：Qwen3.5-Omni 的三阶段训练">

**预训练三阶段**：① 分别把文本、视觉（SigLIP2）、音频（AuT）编码器训练到位；② **模态对齐与联合预训练**，把多模态特征接入 Thinker，用海量图文/音视频-文本数据让它理解多模态；③ 在长上下文、高质量指令数据上激活能力。
**后训练三阶段**：**专家蒸馏**（Specialist Distillation）——把纯文本强推理模型、语音专家模型的能力蒸馏进 Thinker/Talker，避免全模态模型"样样都会、样样不精"；**OPD**（On-Policy Distillation / 策略蒸馏）；**交互对齐 RL**——用强化学习优化真实多轮、可打断、情感表达的语音对话体验。

</Expand>

特色能力还包括：10 种语言的语音理解/生成与拟人情感、零样本声音定制（用用户少量样本克隆音色）、生成带时间同步与场景分割的脚本级字幕、以及 **Audio-Visual Vibe Coding**（直接根据音视频指令编写代码）。

## 8. 重点案例 ②：Kimi K2.5（视觉原生 + 智能体）

月之暗面的 **Kimi K2.5**（2026 年发布，开源多模态智能体模型）走的是**原生视觉融合 + Agent** 路线（据[官方技术报告](https://github.com/MoonshotAI/Kimi-K2.5/blob/master/tech_report.pdf)）。

- **早期视觉融合（early visual fusion）为什么有效**：拼接式只在后期"喂"少量视觉 token，LLM 浅层其实没"看到"图。K2.5 在**整个预训练过程中都以恒定比例把视觉 token 和文本 token 混在一起**（而不是先纯文本训练、最后再接视觉），让骨干的每一层都在跨模态上做注意力——视觉信息不再是"末尾附件"，而是和语言表征共同塑形（co-training），因此视觉定位、OCR、跨模态推理更深。
- **架构三部分**：
  - **MoonViT-3D**：视觉编码器。"3D"指它直接处理**时间×高×宽**的视频体，而不是把视频当一叠静态图。它采用 **NaViT（Native Resolution）打包**——把任意分辨率的图像按 patch 打包成序列，避免"所有图先缩放到固定分辨率"带来的细节损失；对视频，把**最多 4 帧连续画面编成一个时空 token 体**，用一次 3D 注意力覆盖多帧，实现 **约 4 倍时间压缩**（更少 token、更长视频）。
  - **MLP 投影层**：把视觉/视频 token 投影到语言空间（这里的桥因为骨干本身就为多模态训练，作用和拼接式的"外挂桥"不同，更像统一空间里的一次维度对齐）；
  - **Kimi K2 MoE 语言模型**：复用 Kimi K2 的稀疏专家骨干（[MoE](/blog/moe混合专家模型-以deepseek为例/)）。
- **训练三阶段、约 15T tokens**：① 单独把 ViT 训到有意义的视觉表示；② **图文联合预训练**（大量带图 token 的混合数据，落实早期融合）；③ 在高质量数据上训练并激活长上下文——每阶段都保持视觉 token 在场。
- **Agent Swarm**（智能体蜂群）：区别于"一个 Agent 串行做所有事"，它把复杂任务**动态拆成可并行的异构子任务**（比如"查资料""读图表""写代码""验证"同时进行），由编排层调度成百上千个子智能体协同，并用 **PARL**（并行智能体强化学习） 让模型学会"什么时候该分、分给谁、怎么汇合"。结果是部分任务延迟相比单智能体下降到约 **1/4.5**，可自主调度多达约 **100 个子智能体、1500 个协同步骤**。
- 能力侧重：**视觉编程**（Coding with Vision）——对话直接生成前端界面、"看网站交互视频还原代码"、在约 450 万像素的"视觉迷宫"里靠 BFS/路径搜索做视觉推理；以及 100 页级长文档办公。定位是"原生视觉的智能体模型"。

<KimiFigure />

*图 5：Kimi K2.5（示意）——MoonViT-3D 用 NaViT 处理任意分辨率、把多帧编成时空体压缩长视频，MLP 投影后视觉 token 与文本 token 在 Kimi K2 MoE 骨干里全程混排（早期融合），再叠加 Agent Swarm 并行智能体。*

**两个案例的差异**：Qwen3.5-Omni 重点在**全模态的理解 + 语音流式输出**（Thinker-Talker + ARIA，能听能说）；Kimi K2.5 重点在**视觉原生融合 + 大规模并行 Agent**（MoonViT-3D + Agent Swarm）。两者都遵循同一条主线——**从拼接式走向端到端原生融合**，并且都站在了 MoE、Gated DeltaNet、长上下文这些前沿机制上。

## 9. 重点案例 ③：MiniMax H3（全模态"生成"，统一生成音视频）

如果说 Qwen3.5-Omni 偏"全模态理解 + 语音对话"、Kimi K2.5 偏"视觉 Agent"，那 MiniMax H3 则把原生多模态推到了**生成端**：据官方开源公告与 Model Card（2026，资料以官方技术报告为准），H3 是一个**通用全模态生成系统**，统一理解由文本、图像、视频、音频组成的多模态上下文，并能**直接生成带原生立体声音频的视频**（最高 2K、4–15 秒、24 FPS、32 kHz 立体声）。

**先补一个背景：图像/视频是怎么"生成"出来的？** 前面讲的 VLM（理解类）都是自回归地**吐 token**，本质是预测"下一个词"。但生成一张图/一段视频走的是另一套思路——**扩散模型（diffusion）**：

1. 先有一堆**纯噪声**（像电视雪花屏，什么内容都没有）；
2. 模型学着做的事是**去噪**：每一步根据"用户想要什么（文本/参考素材）"，预测这堆噪声里哪些该去掉，一点点补上画面/声音的结构；
3. 重复几十步后，噪声变成清晰的图像/视频。

打个比方：像雕塑家从一整块石头（噪声）里逐步凿出形状，而不是像写字那样一笔一笔往后接。决定"怎么去噪"的大脑，早期用 U-Net（一种卷积网络）；后来的 **DiT（Diffusion Transformer，扩散 Transformer）** 把它换成了我们前面一直在讲的 Transformer——好处是能用上注意力、能规模化、还能像处理语言一样把所有条件都变成 token。MiniMax H3 用的就是一个处理多模态的 DiT，理解这个背景再看它的设计就顺了。

它和前面"拼接视觉模块"完全不同，关键在**单一联合模型**（single-stream omni transformer）。

<Expand title="扩展：单流（single-stream）vs 双流（two-stream）DiT">

视频生成里有两种做法：**双流**（如标准 MMDiT）让视频 token 和文本/条件 token 先各自过部分独立模块、再在交叉注意力里交互；**单流**则把所有模态的 token **拼进同一条序列、用完全相同的一组 self-attention + FFN**。单流的好处是任意两个模态 token 之间都能直接建立注意力——视频某帧和同一时刻的音频 token 就在同一层里"互相看见"，这是音画能在生成时就保持一致的结构原因；代价是序列更长、计算更重。H3 严格说不是经典 MMDiT，而是"带模态专属 AdaLN 的单流多模态 DiT"。

</Expand>

- **统一的生成骨干**：约 **33B 参数、50 层**的 **Dense**（非 MoE） Transformer。关于"去噪"：扩散生成不是一次性输出结果，而是从一份**高斯噪声**（满屏雪花/白噪）出发，经过几十步、每步把噪声"抹掉一点"、补上一点内容，最终得到清晰的视频帧和音频波形；DiT（Diffusion Transformer）就是用 Transformer 来预测"这一步该怎么去噪"。H3 把视觉语义 token、文本 token、参考图/视频/音频的 latent，以及**待生成内容对应的带噪 latent**，全部拼成**一条 packed 序列**送进同一个骨干。
- **三种关键机制**：
  - **联合自注意力**：视频 token、音频 token、条件 token 在同一组注意力里交互，视频每一帧和与它同时刻的音频直接相关联——因此音画是**一起去噪、天然同步**的，而不是"先生成视频再配音/再对齐"。
  - **AdaLN**（自适应层归一化）：把"当前去噪到第几步（扩散时间步）+ 模态类型"作为条件，经调制注入每一层，告诉网络"该在噪声里保留多少信号"。H3 中约一部分参数在 AdaLN 分支里、可预计算缓存。
  - **三维 Multimodal RoPE**：用 (t, h, w) 三个维度的旋转位置编码同时表达**时间（第几帧）和空间（图像的高、宽）**，让模型区分"同位置但不同时刻""同时刻但不同画面位置"。
- **编解码分工**：视频和音频各用一个 **VAE**（变分自编码器） 把原始像素/波形压成紧凑 latent（生成网络在 latent 空间去噪，快且省），生成完再解码回真实视频帧和声音；多模态指令的语义提炼借助 Qwen3-VL。

<H3Figure />

*图 6：MiniMax H3 的单流多模态 DiT（示意）——文本/图像/视频/音频/噪声 latent 拼成一条序列，在同一个 Transformer 里联合去噪，因此视频和音频同步生成。*

- **系统三段式**：**H3-Context-IR** 先理解多模态指令并转成结构化的"上下文中间表示"；**H3-Base** 据此生成 768p 音视频；**H3-Regenerate-2K** 再把结果重生成/超分到 2K（先生成后提画质，也是控制成本的做法）。支持多种宽高比、11 种语言，"全模态参考"输入最多约 9 图 + 3 视频 + 3 音频（可用首尾帧/参考素材引导生成）。
- **代价与取舍**：单流联合去噪的序列极长（视频帧数 × 空间 token + 音频 token 一起进注意力），**推理成本明显高于只输出文本的模型**；这也是它主打开源（33B、可本地跑）、采用"先 768p 再 2K 重绘"分层生成的原因。

<Expand title="扩展：DiT 相比 U-Net 多了什么">

早期扩散模型普遍用 **U-Net**（一种对称的卷积编码器-解码器）做去噪，它擅长图像局部结构，但难扩展、对"文本指令、跨模态条件"的利用不够灵活。DiT 把去噪网络换成 **Transformer 块**，并用 **AdaLN** 把"当前去噪到第几步 + 条件（文本/音频/参考素材）"作为调制信号注入每层。这样一来，视频帧 token、音频 token、文本条件 token 可以直接放进同一条序列做 self-attention——条件对生成的控制更直接、模型也更容易随数据和算力规模化。这正是"一切皆 token"思想从理解侧（LLM/VLM）延伸到生成侧（扩散模型）的体现。

</Expand>

**三个案例合起来看**：原生多模态不只是"理解多模态输入"，还包括"多模态输出"——Qwen3.5-Omni（理解 + 流式语音）、Kimi K2.5（视觉 + Agent）、MiniMax H3（音视频联合生成）分别覆盖了理解、行动、生成三个方向，但底层方法论一致：**统一骨干、早期融合、token 化一切**。

## 10. 原生多模态技术演进总结

把多模态这几年的脉络串成一条时间线，可以看到"怎么让非语言信号进入大模型"在不断深入：

| 阶段 | 代表（年份） | 融合方式 / 关键技术 | 突破 |
| --- | --- | --- | --- |
| **图文对齐基础** | CLIP（2021） | 对比学习，图文进同一语义空间 | 证明视觉/语言可对齐 |
| **拼接式 VLM** | BLIP-2 / LLaVA（2023） | Q-Former / MLP 桥 + 冻结 LLM，late fusion | 低成本让 LLM"看图" |
| **半原生** | Qwen-VL / GPT-4V / Gemini（2023–24） | LLM 参与微调、视觉 token 深度注入、动态分辨率 | 视觉定位、OCR、文档、长图 |
| **原生全模态（理解+语音）** | Qwen3.5-Omni | 端到端、Thinker-Talker、ARIA、Gated DeltaNet | 能听能说、实时流式语音 |
| **原生视觉 Agent** | Kimi K2.5 | 早期视觉融合（MoonViT-3D）、Agent Swarm | 视觉编程、多智能体并行 |
| **原生多模态生成** | MiniMax H3 | 单流多模态 DiT、联合去噪 | 直接生成带音频的视频 |

**技术趋势（四条主线）**：

1. **融合越来越早**：从"末端拼接"到"预训练全程混排"，视觉/语音不再是附件，而是和语言一起塑造骨干（early fusion / co-training）。
2. **骨干越来越统一**：不是每个模态一套模型，而是"一切皆 token"进同一个 Transformer，靠共享参数做跨模态推理。
3. **能力从"理解"走向"行动"与"生成"**：看图问答（理解）→ 视觉编程/Agent（行动）→ 生成带声音的视频（生成），全模态闭环。
4. **工程效率与架构前沿联动**：视觉/音频 token 海量，因此多模态大量复用 **MoE、Gated DeltaNet/线性注意力、FP8/量化、分块预填充** 等长序列与成本优化——多模态模型往往是前面所有技术的"集大成"。

一句话总结：**多模态的演进史，就是"模态接入点"不断前移、"统一骨干"不断加深、"能力"从理解扩展到行动和生成的过程；而每一步都在和长序列成本做博弈。**

## 11. 小结

多模态这篇文章可以压缩成一句话：**核心难点是把连续的图像/语音对齐到语言空间，主线是从"拼接式（冻结 LLM + 外挂桥，晚期融合）"走向"原生多模态（端到端、早期融合、统一骨干）"**。

- 只想让 LLM 快速看图问答：拼接式（ViT/CLIP + MLP/Q-Former + LLM）依然最成熟、成本最低；
- 要能听能说、长视频、视觉 Agent、音视频生成：走原生路线，代价是更大的训练数据/算力；
- 而工程上绕不开的共同课题是**视觉/音频 token 太多、序列太长**——这正是本博客前面讲的 [MoE](/blog/moe混合专家模型-以deepseek为例/)、[线性注意力/Gated DeltaNet](/blog/线性注意力为何回归-gated-deltanet/)、[注意力机制演进](/blog/注意力机制演进-从mha到gqa与mla/)、[量化](/blog/大模型量化-用更少的显存跑更大的模型/) 在多模态里集大成的原因。Qwen3.5-Omni、Kimi K2.5、MiniMax H3 就是这条路线的国产代表。

## 自测（答案点击展开）

**Q1. 拼接式模型里的"桥接模块"（如 LLaVA 的 MLP、BLIP-2 的 Q-Former）解决什么问题？它属于早期还是晚期融合？**

<Expand title="查看答案">

解决"视觉特征怎么变成 LLM 能接收的语言空间嵌入"：编码器产出的视觉向量维度/分布和词嵌入不一致，桥接把它对齐、投影成 LLM 的输入 token。它属于**晚期融合**（late fusion）——视觉信息在冻结 LLM 的输入端才拼接进去，LLM 权重不为视觉做深层调整。Q-Former 还额外用可学习 query 做交叉注意力、压缩出少量关键视觉 token。

</Expand>

**Q2. 原生多模态相比拼接式，最大的结构差异是什么？为什么跨模态能力通常更强？**

<Expand title="查看答案">

差异在于**融合时机和训练方式**：原生多模态从预训练起就让文本、图像、语音 token 在**同一个骨干的所有层**里混排、端到端训练（早期融合 early fusion），而不是冻结 LLM、只在末端外挂桥。这样视觉/语音信息在每一层都参与注意力与推理，跨模态交互深、共享同一套表征，因此在视觉定位、长视频时序、跨模态推理乃至语音输出上更强；代价是训练数据和算力需求大得多。

</Expand>

**Q3. Qwen3.5-Omni 的 ARIA 解决什么问题？为什么它和 Gated DeltaNet 都和"长序列/流式"有关？**

<Expand title="查看答案">

ARIA（自适应交错对齐）解决**文本和语音生成速率不匹配**：直接双通道生成会漏字、错音、数字读错、流式不稳；ARIA 把文本/语音统一成单通道交错流、动态对齐。Gated DeltaNet 则是线性注意力机制，让状态/KV 不随上下文增长，用于超长音视频序列、降低 KV-Cache 开销。二者都服务于"长音视频 + 流式语音"这个场景——一个保证语音和文本同步稳定，一个保证超长序列推理高效省显存。

</Expand>
