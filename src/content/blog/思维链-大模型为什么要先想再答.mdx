先算一道题：**37 × 48 等于多少？** 口算很容易出错（进位容易乱）。但拿出一张纸列竖式，先算 37×8=296，再算 37×40=1480，最后错位相加得 1776——大多数人都能算对。纸没有让你变聪明，它只是让你**把中间结果写下来、一步一步算**。

大模型也有同样的现象。直接问它答案，经常答错；要求它「一步步想」，先输出中间推理、最后给答案，正确率明显提高。这就是**思维链（Chain-of-Thought，简称 CoT）**。2024 年之后的「推理模型」（o1、DeepSeek-R1、Qwen3 等）更是把这件事做到了极致：回答前先写几千甚至上万个 token 的「思考过程」。

本文回答三个问题：

1. 为什么把步骤写出来，模型就更准？模型不是本来就会吗？
2. 「会推理」是怎么从一句提示词，变成可以训练出来的能力的？
3. 思考要花钱花时间——什么时候该让它想，什么时候不该？

阅读门槛：读过[《图解大模型（入门篇）》](/blog/图解大模型-一口气搞懂大模型的骨架/)即可——你需要知道自回归（一个词一个词往后接）、KV Cache、采样、SFT/RLHF。

- **test-time compute（答题时算力）**：模型训练好之后、回答每个问题时投入的计算量。思维链越长，投入越多。与「训练算力」相对。
- **涌现（emergence）**：能力似乎只在模型大到某个规模后才突然出现的现象。本文会讲到这个说法后来被两方面修正。
- **RLVR（可验证奖励强化学习）**：用程序自动判断答案对错（数学答案匹配、代码跑测试），以此为奖励训练模型，不需要人逐条标注。
- **GRPO**：DeepSeekMath 提出的一种 RL 算法，用同一题多个答案的组内相对好坏来估计优势，不需要额外训练一个 critic 网络。
- **pass@k / majority@k**：两种评测口径。pass@k 是采样 k 次只要有一次对就算对；majority@k 是采样 k 次取多数投票答案。比较模型时必须对齐。

## 1. 什么是思维链

**定义**：模型在给出最终答案之前，先生成一连串中间推理的 token。这些 token 有个关键性质——它们是模型自己采样出来的，随后又成为自己下一步的输入（进入 KV Cache）。换句话说，模型一边写、一边读自己刚写的内容。

<CotDirectFigure />

*图 1：同一道题、同一个模型、同一套参数，区别只在生成多少 token。多写的每一步，都是多做的一次计算。*

有两种经典的触发方式，都发表于 2022 年：

- **少样本思维链（few-shot CoT）**[1]：在提示里先给两三个「问题 → 带过程的解答 → 答案」的范例，再问新题，模型会模仿这个格式。Wei 等人在 5400 亿参数的 PaLM 上发现，GSM8K 小学数学题的正确率从 17.9% 提升到 56.9%。
- **零样本思维链（zero-shot CoT）**[2]：一个范例都不给，只在问题后面加一句「Let's think step by step（让我们一步步想）」，也能触发分步推理。

### 1.1 一个被两次修正的观察：小模型不能用思维链吗

2022 年 Wei 等人在提出少样本思维链的论文 [1]（§3.2）里，报告了思维链提示与模型规模的关系。论文有两句关键的原始表述：

> 原文一（小模型上的表现）："chain-of-thought prompting **does not positively impact performance for small models**... smaller scale produced fluent but illogical chains of thought, leading to **lower performance than standard prompting**."
> （思维链提示对小模型没有正向作用；小模型写出的思维链语言流畅但逻辑不通，成绩反而低于普通提示。）
>
> 原文二（增益何时出现）："chain-of-thought prompting is **an emergent ability of model scale**... only yields performance gains when used with models of **~100B parameters**."
> （思维链提示是模型规模的涌现能力，约 100B 参数规模才出现增益。）

这两句各自包含一个可以独立检验的观点，后面的两项研究恰好分别只修正其中一个：

- **观点一（增益如何出现）**：思维链增益约在 100B 规模处「涌现」，存在一条规模门槛；
- **观点二（门槛之下有没有用）**：小模型上思维链提示无效，甚至比普通提示更差。

**修正一：所谓「涌现」，主要是非连续计分指标造成的测量现象（针对观点一）。**

Schaeffer 等人（NeurIPS 2023 最佳论文）[7]指出，模型的单步能力随规模和训练量是连续改善的，但论文使用的是「整题全对 / 全错」这类非连续指标。以一道 8 步的题为例，假设模型每一步做对的概率为 $s$，整题全对的概率约为 $s^8$（自造示意，非论文实测）：

| 单步正确率 $s$ | 0.5 | 0.7 | 0.9 |
| --- | --- | --- | --- |
| 整题全对率 $s^8$ | 0.4% | 5.8% | 43% |

单步能力从 0.5 连续提高到 0.9，按整题对错计分时，成绩却表现为长期接近零、随后突然上升——连续改善被非线性的计分方式呈现为「涌现」；评测样本量较小时，前两档实测经常就是零。改用连续指标（按答对的步骤数、token 匹配程度计分）后，小模型的成绩曲线是渐进上升的，观点一所说的约 100B 硬门槛在测量上并不成立。

这项修正的范围要划清：它讨论的是「增益—规模」曲线的形状，**并没有让小模型实际取得好的思维链成绩**——观点二报告的经验事实此时原封不动。

**修正二：小模型缺的是推理训练，不是规模（针对观点二）。**

2025 年 DeepSeek-R1 把长推理轨迹蒸馏进 1.5B–70B 的模型，小模型在数学、代码上也能完成像样的分步推理 [14]；R1-Zero 进一步表明这种行为可以由强化学习直接产生。这限定了观点二的成立范围：Wei 等人实验中的小模型是**未受推理训练的模型**，它们在思维链上失败，缺的是相应训练而非「小」本身；2022 年实验中规模之所以与表现相关，是因为大模型在更多数学、代码语料上做过预训练，规模只是相关训练量的代理变量。

观点二没有被完全推翻：**未受过推理训练的小模型，仅靠提示词，今天仍然用不好思维链**——被推翻的是把这个结论外推为「小模型无论如何都不行」。

**两项修正与原观点的对应关系：**

| 原观点（Wei et al., 2022） | 修正研究 | 修正后的准确表述 | 仍然成立的部分 |
| --- | --- | --- | --- |
| 一：思维链增益约在 100B 规模涌现，存在门槛 | Schaeffer et al., 2023 [7] | 主要是非连续计分指标造成的测量现象，连续指标下不存在硬门槛 | 小模型的绝对成绩仍然低 |
| 二：小模型上思维链提示无效甚至更差 | R1 蒸馏 / RL, 2025 [14] | 失败原因是缺少推理训练，不是规模本身 | 未训练 + 仅提示词，仍然无效 |

平衡地说，规模依赖今天依然真实存在（小推理模型在最难的任务上仍明显弱于大模型），但它不是一条硬阈值——所谓「涌现」是测量方式的产物，所谓「小模型无效」则可以被推理训练改写。

### 1.2 现代形态：一段「思考」加一段「答案」

今天的推理模型把思维链内化进了标准输出格式：先输出一段思考过程，再给最终答案。以 Qwen3、R1 生态为例，思考内容包在一对专门的标签之间：开头先输出 `<think>`，推理结束时模型自己采样出 `</think>`，此后的 token 转向正式答案；DeepSeek 官方 API 正是据此把回复拆成 `reasoning_content` 和 `content` 两个字段。

模型怎么知道哪段是思考、何时该给答案？没有任何外部信号——**边界是从训练数据里学来的概率规律，不是硬状态机**：SFT 语料把长推理统一包在这对标签里，模型学到的是「开头先出起始标签、写完推理后该出结束标签」；结束标签和其他 token 一样，是模型自己采样出来的。生成答案时，注意力能读到前面全部思考 token，答案因此建立在思考结果上。这套机制也会失灵：模型偶尔忘记输出结束标签或格式错乱，需要服务端做兜底解析；R1-Zero 当年可读性差、格式混乱，正是靠冷启动 SFT 治好的。

注意一个对模型而言的事实：**思考 token 和答案 token 在模型看来没有本质区别**，都是上下文中的普通 token，都参与注意力、都写入 KV Cache。「用户能不能看到思考原文」纯粹是产品层的设置，各家差异很大（见第 5 节附录）。

顺带厘清一个叫法：**「深度思考」和思维链在机制上是同一个东西**——都是把中间计算摊到生成的 token 上；区别只在两代形态：2022 年的思维链是临时的提示词技巧，不这么问它就不想；「深度思考」（o1、R1 类）是长 CoT 被训练进了权重、并配上固定标签格式与思考预算控制的默认工作模式。一句话：**深度思考 = 被训练成习惯、且工程化了的长思维链。**

在解释机制之前先埋一个问题，读完第 2.3 节再回来：**我们看到的那串「思考」，一定是模型得出答案的真实思路吗？**

## 2. 为什么有效（以及什么时候无效）

### 2.1 机制：把计算「摊」到一个个 token 上

先用一句话建立直觉：思维链像自言自语——模型「说」出的每一步，下一步自己还能「听」到。下面用机制语言准确描述这一过程，有三个要点：

1. **中间 token 写入序列，参与后续每一步计算。** 思维 token 与普通 token 在表示上没有区别：生成后写入 KV Cache，在后续每一步前向中作为注意力的键值被读取，不会在生成后消失。
2. **每个思维 token 对应一次完整的网络前向。** 自回归生成中，每产生一个 token，固定层数的网络都要完整执行一次。生成 $n$ 个思维 token，等价于将同一网络串行执行 $n$ 次——这就是「答题时算力」的实际来源。
3. **注意力对前文是软选择，不保证使用中间结果。** 模型是否利用已生成的中间步骤，取决于注意力权重，没有强制读取机制。这既意味着错误前提不会被自动纠正（见 2.2 节），也意味着外显的推理链不一定是得出答案的真实因果路径（见 2.3 节）。

<CotScratchFigure />

*图 2：每个思维 token 由一次完整前向生成，写入 KV Cache 后在下一步被读取。*

这套机制为什么能提高正确率？三条相互独立的理由：

- **串行计算深度累加（外部工作记忆 scratchpad）**[4]：单次前向能够完成的串行变换深度受网络层数限制；中间结果外化到序列后，后续前向可以直接建立在这些结果之上，可完成的串行计算深度随步数增长，不再受单层网络深度限制。Feng 等人 2023 年从表达力角度给出了形式化结论：有界深度的 Transformer 直接解某些串行问题需要超大参数量，而允许输出中间步骤时，常数规模的自回归 Transformer 就能解 [8]（构造性理论结果，说明「摊开计算」在数学上可行，不等于真实网络的机制已被完全证实）。
- **任务分解**：多步难题被改写成一串条件于前文的单步小题，每个单步更可能落在模型已有的能力范围内。
- **训练分布匹配**：训练语料里，数学解答、代码、教程本来就是「先过程后结论」的形式；按这个格式生成，走的是模型见过最多、最熟练的路径（代码天然一步步执行，这也是推理能力先在代码上显现的原因之一）。

> **一句话总纲：思维链不增加知识，只重新分配答题时的计算；它让模型够到自己已有能力的边界，但不能无中生有。**

### 2.2 什么时候会失效

这套机制依赖四个前提，前提被打破时思维链就失灵：任务**可以**拆成串行子步骤；每一步比原题简单；后面的步骤**真的用到**前面的结果；模型本来就具备单步能力。具体有四类典型失效：

- **简单任务不需要，甚至更差。** 闲聊、简单改写、单跳事实问答（「法国首都是哪」）本来一步就能答对，强制思考只会更慢、更啰嗦，还可能把简单问题想复杂；已有研究在简单任务上观察到思维链降低表现 [17][18]。
- **错误会沿链累积。** 第一步说错，后面每一步都建立在错误前提上，错得越来越远——而注意力是软选择，模型并不会自动「听到」前面的错并纠正。
- **可能说出看似合理的错误步骤。** 语言流畅 ≠ 推理正确。
- **链长不等于深度。** 注水、重复、车轱辘话式的「思考」不会提高正确率，反而有害。

### 2.3 忠实性：展示的推理链是真实思路吗

还有一个边界不属于「有没有效果」，而属于「该怎么解读这条链」：**模型展示的推理链，未必是它得出答案的真实因果路径。** Turpin 等人 2023 年发现 [5]：给模型一个错误暗示（比如偷偷带偏的答案），它经常会写出头头是道的推理链去迎合那个预设答案；在他们的实验里，带偏见的提示下模型准确率最多掉 36 个百分点，73% 的不忠实思维链显式附和了偏见——「先定答案、再编理由」真实存在。

但也不能倒向「思维链全是编的」。Lanham 等人 2023 年做了反向干预实验 [6]：**篡改或删除思维链的前几步，后续答案经常随之改变**——说明思维链在很多情况下确实参与了因果，不只是装饰。

平衡的结论：**思维链是「外显的计算轨迹」，不是「内心独白的录音」**——既非可靠自白，也非无关装饰。经过 RL 训练的推理模型，思考链与正确结果被奖励「缠」得更紧，但忠实性仍不被保证。实践含义放在第 7 节：思维链应当被当作**审计线索**而不是**保证书**，重要结论要独立验算。

## 3. 从「提示技巧」到「训练出来的能力」

2022 年的思维链只是提示词技巧，模型本身一行没改。两年后，「会推理」成了训练出来的能力。这中间发生了什么？

先明确一件容易被「训练」两个字带偏的事：**这条路线从头到尾只调整模型权重，不重新设计模型结构。** 最直接的证据是 3.2 节的 R1-Zero——它直接在 DeepSeek-V3 这个现成基座上做 RL，网络一行没改，长推理行为就出现了；同一节的蒸馏实验也同样是结构不动、只微调权重。但有三件「不是结构、却必须配套」的事：① chat 模板里要加入思考段的起止标签（1.2 节）；② 要搭起可验证任务、组采样这套 RL 基础设施；③ 「不用改结构」有个隐性前提——基座得足够大、且在数学和代码语料上预训练过。RL 更像筛选和放大预训练里已有的推理雏形（见本节后文），在太小的模型上怎么调权重都出不来。

在讲时间线之前，先补一块零基础铺垫：**用强化学习训练语言模型，具体在做什么操作。**

### 3.0 预备：不讲公式，RL 训练的四拍

下面以 RLVR 为例走一遍 RL 训练的四个步骤。这四步是所有 RL 微调的通用流程，RLHF 同样适用；两类方法的区别只在第二拍——RLVR 由程序验证器打分，RLHF 由人类偏好训练出的奖励模型打分。

**第一拍：自己做。** 给模型一道题，让它用采样（还记得入门篇讲的温度吗？温度大于 0 就有随机性）一次性生成多个**完整**解答。随机性在这里是优点——它提供了探索，同一道题能得到好几种不同做法。

**第二拍：对答案。** 答案对不对，由程序自动判定：

- **数学题**：模型被要求把最终答案用统一格式写在回复末尾的 LaTeX 方框里（形如 $\boxed{42}$）；程序只提取方框里的结果（42）与标准答案做符号比对，不看前面的推导和措辞；
- **代码题**：编译生成的程序、自动跑测试用例。

整个过程不需要人写推理过程、也不需要人逐条打分，可以无限规模化。这种奖励叫**可验证奖励（RLVR）**。

**第三拍：分高低。** 把同一道题的一组解答放在一起比：高于组内平均水平的算「好轨迹」，低于的算「差轨迹」。

**第四拍：改习惯。** 调整模型权重，让好轨迹里出现过的 token 序列下次更容易被采样出来，差轨迹更不容易出现。注意三句话：(1) 模型**不背题、不存题库**，改的是下次生成各个 token 的概率倾向——像练球形成的肌肉记忆，相似局面下高胜率动作更容易自动冒出来；(2) 考的永远是没见过的**新题**，记住具体答案没有任何收益，泛化才是目标；(3) 程序通常只知道最终答案对错、不知道具体哪一步立功，于是**整条轨迹一起被强化**（这叫信用分配）——规模大了，这种粗糙做法居然有效。

这也解释了数学和代码为什么成为推理训练的突破口：它们的答案便宜、客观、可以无限自动判分；开放写作类任务答案难判，至今仍主要靠奖励模型。

还要提前给「顿悟」叙事降温：基座模型在大规模代码、数学语料的预训练里，**本来就已经出现过拆分、验证、回溯这类行为的雏形**。RL 更像是在**筛选、串联和放大**这些已有的倾向，而不是凭空发明了推理——「aha moment」更接近「少数随机尝试碰巧走通、被奖励机制保留并放大」的选择效应，至于这算不算真正的「顿悟」，学界仍有争论（3.2 节）。

### 3.2 DeepSeek-R1：开源推理模型的完整样本

R1 技术报告里最受关注的是 **DeepSeek-R1-Zero**（官方全名，没有「R1-Z」这个型号；671B 总参 / 37B 激活的 MoE，权重随报告以 MIT 协议开源）[14]：它**直接在基座模型上做 RLVR，跳过了监督微调冷启动**，训练中模型自发地把回复越写越长，出现了反思、自检、回退重做等行为，论文用「aha moment」描述过一个训练后期主动纠错的案例。

有三个限定必须讲清楚：

1. 「自发反思」在论文里是**行为观察**，「aha moment」只是一个**定性的案例研究**，不是统计结论；
2. R1-Zero 同时有明显缺陷：无限重复、可读性差、**中英文混杂**——这正是正式版 R1 要加冷启动 SFT 和「语言一致性奖励」的原因；
3. 「RL 凭空创造了推理」这个归因有争议。后续研究发现，基座模型在 RL 之前就会产出 "wait / let me verify" 类 token，且 GRPO 存在偏好长回答的长度偏差 [15]；也有研究主张未必存在所谓「aha moment」。稳妥的说法是：**RL 至少部分是在筛选和放大预训练里已有的倾向。**

正式版 **R1** 是完整的四阶段流程（细节见折叠），其中第二阶段（推理向 RL）只用规则奖励（答案正确性、格式、语言一致性），而第四阶段（全场景 RL）重新引入了奖励模型来处理帮助性、无害性这些无法程序化判分的开放目标。

<Expand title="折叠：R1 的四阶段与 GRPO">

**四阶段**：① 冷启动 SFT（用少量高质量长推理数据微调，解决可读性和语言混杂）→ ② 推理向 RL（规则奖励：答案正确、格式规范、语言一致；语言一致性奖励有轻微性能代价但保留）→ ③ 拒绝采样 SFT（用②的模型生成、按正确性筛选数据再微调）→ ④ 全场景 RL（面向各类通用任务，引入奖励模型）。

**GRPO** 出自更早的 DeepSeekMath 论文（2024-02）[12]，不是 R1 发明的。传统 PPO 类方法要额外训练一个 critic 网络来估计「这个状态平均该得多少分」；GRPO 省掉它：对同一道题采样一组（Group）完整解答，直接用**组内平均分**当基线，每条答案的奖励减去组均值就是「优势」。这天然抵消了「这道题本身是难是易」的影响，实现更简单。已知的副作用之一是对回答长度有偏好，实践中要校正。

</Expand>

**R1 的蒸馏实验：推理能力可以外溢给小模型。** R1 报告了一个影响深远的实验：把 R1 生成的长推理轨迹当作 SFT 数据，蒸馏进 1.5B 到 70B 的通用模型（Qwen、LLaMA 系列），小模型在数学、代码上大幅提升 [14]。要准确理解蒸馏的是什么：**蒸进去的是「分步推理的行为分布」（用长 CoT 数据做微调），不是注入了一个「推理模块」，也不是复制了大模型的全部能力。** 小模型有收益，也有明显天花板，且会继承蒸馏数据的语言与风格。这也为 1.1 节观点二的修正提供了直接依据。

### 3.3 实践入口：自己训出深度思考的两条路

拿一个不会深度思考的模型自己动手，开源社区已经复现过，两条路难度差很多：

| 路径 | 做法 | 适合谁 |
| --- | --- | --- |
| RLVR（R1-Zero 式） | 直接在基座上用规则判分的 RL（GRPO），从数学、代码这类答案可自动验证的任务起步 | 有 RL 训练栈与算力；会遇到 R1-Zero 同款的语言混杂、无限重复问题，通常要补冷启动 SFT 和格式、语言一致性奖励 |
| 蒸馏 SFT（最省事） | 拿 R1 等模型生成、并按正确性筛选过的长推理轨迹当 SFT 数据微调 | 小规模也能做；R1 论文验证过 1.5B 到 70B 都有收益 |

两条路都要记住同一个天花板：**调得动「分步想的行为」，调不出大模型的全部能力**——推理质量受基座容量硬约束；蒸馏还会继承数据的语言与风格；微调之后 chat 模板和服务端标签解析也必须配套。

## 4. 成本账：思考 token 到底贵在哪

### 4.1 精确的复杂度

思考阶段本质上是一个**超长的 decode（逐词生成）阶段**。回顾入门篇：

- 生成第 $i$ 个思维 token 时，要对当前上下文中全部 $n+i$ 个位置做一次注意力，单步是 **$O(n+i)$** 的计算和 KV 读取；每步的主要开销仍是把权重从显存搬到片上（带宽受限；R1 这类 MoE 模型每个 token 只激活部分专家，这也是它 token 单价能压低的原因之一）。
- 生成 $m$ 个思维 token，注意力累计为

$$
\sum_{i=0}^{m} O(n+i)=O(mn+m^2)
$$

推理模型通常 $m\gg n$（提示一两千、思考一两万），这时近似为 $O(m^2)$。注意 prefill（处理输入）和 decode（生成思考）要分开算，二次项几乎全部来自超长 decode 的累积。
- **KV Cache 是线性 $O(m)$ 显存**，但线性就足够致命：几万个思维 token 的 KV 以 GB 计，直接决定单张卡能同时服务几个请求（并发容量）。

推理负载因此是**极度 decode 主导**的：DeepSeek 的 ARES 系统论文报告其生产集群中 prefill 节点与 decode 节点的规模约为 32 : 320 [20]——每 1 个 prefill 节点要配约 10 个 decode 节点。

### 4.2 三重成本

1. **延迟**：思考发生在最终答案之前，用户要等。注意它影响的是**总响应时间**，不影响首 token 延迟（TTFT，首 token 反而是思考的第一个 token，很快就出来）。
2. **费用**：思维 token **一律按输出 token 计费**（输出价通常是输入价的数倍），并且与最终答案**共享输出长度上限**。一个上线排名第一的事故：`max_tokens` 设得太小，思考把额度用完，最终答案为空。多轮对话中，按厂商要求回传的思考内容下一轮还会按**输入**再计一次费（见附录表）。
3. **显存/容量**：KV Cache 压低并发数（见 4.1）。

思维链有多长？数字按出处分层看：R1 论文中 RL 训练时平均响应长度从**数百涨到数千**（Figure 3 的定性趋势），评测时最大生成长度设到 32,768 [14]；新版本（R1-0528）在同一套 AIME 题上平均思考量从约 1.2 万涨到约 2.3 万 token，同时正确率从约 70% 升到 87.5%（官方更新公告口径，属**评测期**统计，不是训练曲线）——「思考通胀」本身是 2025 年的明显趋势。

### 4.3 思考预算：想多少才合适

产品形态要分三层，别把研究方向当成现成功能：

| 层次 | 状态（截至 2026-09） | 例子 |
| --- | --- | --- |
| 开发者手选固定档位 | 主流、默认形态 | OpenAI 的 `reasoning_effort`、Claude 的 thinking budget、Gemini 的 thinkingBudget、Qwen3 的 `thinking_budget` |
| 档位内的自适应 | 已上线可用 | Gemini dynamic、新型号在选定档位内自行分配思考长度 |
| 按题目难度学习分配、早停、验证器路由 | **基本仍是研究** | Snell 等人的 per-prompt 最优策略 [13]；工程近似品是外部模型路由和 max_tokens 截断 |

还要区分**硬截断和优雅早停**：`max_tokens` 把思考砍在半句会产生空回答；有社区复现分析发现，部分开源实现的「预算收口」表现为生成一段固定的收尾话术，而非真正基于置信度的早停（社区观察，非官方结论），云端接口才有原生预算支持。

### 4.4 关键结论：思考不是越多越好

Snell 等人 2024 年系统研究了答题时算力的最优分配 [13]，按题目难度（pass@1 成功率）分档，结论反直觉：

- **简单题**：并行采样几条取最好（best-of-N）最稳；给单条链堆搜索预算反而可能更差（过程奖励被「钻空子」，模型学会说重复的废话、写超短解答）；
- **中等题**：过程奖励引导的束搜索稳定更好，值得投入；
- **最难题（pass@1 接近 0）**：**所有 test-time 方法都救不回来**——答题时算力不能凭空造出模型没有的能力，得换更强的模型。
- 按难度分配预算（简单题早停、难题集中投入）可以在同等效果下**最多省约 4 倍算力**；论文标题里「小模型加大算力打赢 14 倍大模型」是**有前提的**（小模型本来就有非零成功率的区间），不是普遍规律。

2025 年的实证进一步发现了**倒 U 形**：在 R1 **蒸馏小模型**（1.5B/7B 量级）的 MATH-500 实验中，成绩随思考长度先升（82.2%→87.3%）后降（长链回到 70.3%）[17]；简单任务上还会出现无产出的反思循环 [18]；Kimi k1.5 训练时**专门加了长度惩罚**防止过度思考 [16]。注意倒 U 数字来自小模型实验，不是大模型的普遍定律，但「过度思考有害」在各尺度都有报告。

## 5. 工程现实：使用推理模型的坑

### 5.1 思考与工具调用

推理模型调用函数/工具的基本范式是 **think-then-act：先想完，再行动**，而不是在思考中途发起调用。R1 首发时并不支持 function calling / JSON 输出，2025 年中的更新才补上 API 支持（注意这与后来 V3.2 把「思考与工具调用」做进**训练**是两个不同层面的事）。

需要多轮工具时，就产生了**交错思考（interleaved thinking）**：调用工具拿到结果后，再想一轮。各家的串联方式不同：Claude 用带加密签名的 thinking block，DeepSeek 用 `reasoning_content`，Gemini 用 thought signature，OpenAI 的推理内容不下发、靠服务端加密串联。这些思考内容在多轮工具调用中通常**必须原样回传**，否则直接报错（如 DeepSeek 带 tools 时历史 `reasoning_content` 缺失会返回 400）。

采样参数也有特殊约束（以各家官方文档为准）：R1/Qwen3 官方推荐温度约 0.6、明确不建议 greedy；Claude 开启 extended thinking 时温度被强制为 1、top_p 限定 ≥0.95；旧版 o 系列则忽略温度参数。一个连带结论：**self-consistency 投票需要温度大于 0 才有多样性，低温下多条采样会退化成重复答案。**

### 5.2 与推理优化的关系：投机解码帮得上吗

[前文《投机解码》](/blog/投机解码-小模型打草稿大模型一次批改/)讲的是用小模型打草稿、大模型并行验证来省 decode 延迟。它对长思维链**原则上适用**（思考阶段正是超长 decode），但**收益由草稿接受率决定，而不由输出长度决定**：

- SCoT 论文在 R1 蒸馏模型上实测：短序列有约 1.6–1.9× 加速，但在超过 5k token 的奥赛难题上，外挂草稿的朴素投机解码**反而更慢** [19]。论文提出的解释（属于论文的分析假说）是：推理轨迹多解（同一正确答案对应多条不同路径，token 级精确匹配的接受准则会误杀）、思考标签处熵高、为通用场景训练的草稿头在 RL 后的推理分布上失配；
- 有效的正面路线也存在：模型自带的原生 MTP 头（部署报告称 R1-0528 的原生 MTP 在 3 个投机 token 时吞吐提升约 60%）、为推理数据微调过的 EAGLE 头、以及在「思考段落」粒度（而非 token 粒度）打草稿的 thought-level drafting（SCoT 报告延迟降低 21%–66%）[19]。
- 这类优化属于**自托管**话题（vLLM/SGLang 等），直接调 API 用不到；并且它省的是墙钟延迟，**不省 token 总数，也不阻止 KV 增长**——该付的输出费用一份不少。

顺带一提部署形态：推理负载短输入、超长输出，decode 占绝对大头；PD（prefill/decode）分离架构下跨网络搬运 KV 可能抵消收益，同机 NVLink 或 Mooncake、NIXL 类高速连接器往往优于跨节点分离 [20]。

| OpenAI（o 系 / GPT-5.x） | `reasoning_effort` 档位；**GPT-5.1 起默认 `none`，不显式指定等于关闭思考**（与 GPT-5 默认 medium 不同，升级最易踩） | 原文不下发，只给 usage 计数或摘要；禁止绕过手段提取 | 默认不跨轮保留；可选跨轮保留时按输入计费 | 加密推理内容串联 | 旧 o 系忽略温度 |
| Anthropic Claude | thinking budget（新型号为 adaptive thinking + effort） | 完整 thinking block 可见、带加密签名 | 保留的 block 下一轮按输入计费；工具轮必须原样回传 | 支持交错思考 | 开思考时温度强制 1、top_p≥0.95 |
| DeepSeek（R1 / V3.x 思考模式） | 模型档位，无 effort 参数 | `reasoning_content` 全文可见 | 不带 tools 时历史思考自动丢弃；**带 tools 时必须回传，否则 400** | think-then-act，交错需回传 | 推荐温度约 0.6，不建议 greedy |
| Qwen3 | `enable_thinking` + `thinking_budget`（-1 不限）；也有 /think 软开关 | 开源权重可看全部 think 标签 | 云端默认剥离历史 reasoning，可配置保留（保留即按输入计费） | 多步工具每步前可出思考块 | 推荐温度约 0.6 |
| Google Gemini | 2.5 系 thinkingBudget（0 关 / -1 动态 / 数值）；3.x 系为 thinkingLevel | 返回思考片段；3.x 系以签名 + 可选摘要为主 | 函数调用靠 thought signature 串联、须回传（按输入计费） | 签名串联 | 以官方文档为准 |

共性：思考**按输出价计费**、与答案**共享输出额度**；调整 effort/预算可能使前缀缓存失效。参考链接见文末官方文档清单。

</Expand>

### 5.3 其他工程提醒（折叠）

<Expand title="上线前值得知道的几件事">

- **预算太小 = 空回答**：思考耗尽 max_tokens 后没有答案，务必留足输出额度并处理空答案。
- **改预算会击穿缓存**：含历史消息的 prompt 缓存是按前缀匹配的，换 effort/档位可能让整段缓存失效，延迟和费用一起上升；大预算离线任务考虑 Batch API。
- **长度方差极大**：同一模型不同题目的思考长度可能差十几倍，给调度和限流带来麻烦，按预测长度做调度是工程课题。
- **思考不是可信审计材料，也不是安全边界**：Turpin 式的迎合在思考段里照样发生；提示注入可以影响思考内容；日志是否留存思考原文要过合规审查。
- **蒸馏小模型更早饱和**：长度收益曲线比大模型陡，别直接照搬大模型的预算设置。

</Expand>

## 6. CoT 家族：从一条线到一棵树

先给统一视角：**「提示派」在不改权重的前提下分配更多答题时算力；「训练派」把「何时想、怎么想」学进权重——两派可以叠加。**

| 方法 | 一句话画面 | 结构 | 采样次数 | 用工具 | 成本 |
| --- | --- | --- | --- | --- | --- |
| 标准 CoT [1][2] | 一条线写到答案 | 线性 | 1 | 否 | 低 |
| Self-Consistency [3] | 做五遍，选多数答案 | 线性 ×k | k（温度&gt;0） | 否 | ×k |
| ToT（Tree of Thoughts）[11] | 分叉、评估、剪枝 | 树搜索 | 多 | 否 | 高 |
| ReAct [10] | 想一步、查一下、再想 | 线性 + 工具 | 1 | 是 | 中 |
| Self-Refine / Reflexion | 写完自己批评，再改 | 线性多轮 | 多 | 视情况 | 中 |
| GoT（Graph of Thoughts） | 多条思路还能合并 | 图搜索 | 多 | 否 | 很高（了解即可） |

两个易错点：Self-Consistency 是对**最终答案**投票（不是对推理文本投票），且温度必须大于 0，否则 k 条几乎一样、投票无意义；多数也可能错——同一个模型有共享的系统性偏差。ReAct（2022）[10] 是今天 agent「推理 + 工具调用」范式的雏形，和 5.1 节的 think-then-act 一脉相承。

## 7. 实践：什么时候让模型想

**推荐开启思考**：多步数学与逻辑、复杂代码与调试、多约束规划、长文档多跳分析、需要权衡取舍的设计问题。

**不推荐（或用低档位）**：闲聊、翻译与简单改写、单跳事实问答、分类抽取类高频任务——更慢更贵，过度思考还可能出错。

**症状 → 检测 → 动作**：

| 症状 | 怎么发现 | 怎么办 |
| --- | --- | --- |
| 第一步就错，后面全偏 | 验算最终结论、抽查首步假设 | 要求先列已知与假设；换一种问法/换路径重算 |
| 迎合预设答案、编理由 | 不给暗示时答案是否变化 | 重要结论独立验证，把思维链当审计线索而非保证书 |
| 被错误前提锁死 | 思考里出现未经证实的断言 | 要求模型显式列出假设并自己质疑；提供事实锚点 |
| 跑题、语言混杂、车轱辘话 | 思考长度异常、重复句 | 设思考预算；换用思考/非思考可切换的模型档位 |
| 投票没效果 | k 条答案高度雷同 | 提高温度（0.6–1），确保采样多样性 |
| 多数人也错 | 多条链错在同一处 | 这是模型能力边界（系统偏差），换更强模型或外接工具/检索 |

两个时代差提醒：① 「一步步想」「Let's think step by step」这类**咒语**对 2022 年的旧模型收益大；对 R1/Qwen3 这类已经把思考策略训练进权重的模型，外部提示收益变小甚至多余——它们默认就会想，控制手段是档位/预算而不是咒语。② 简单任务用快模型或非思考档、难任务再升级（模型路由），往往比「所有请求都开最大思考」省钱得多。

## 8. 收束

- **本质**：思维链把模型的串行计算显式化——用答题时生成的 token 换正确率；每一个思维 token 都是一次完整的网络前向。
- **边界**：它不增加知识，只重新分配计算；错误会累积、链长不等于深度、思考轨迹不是内心独白的录音、收益非单调（过度思考会反噬）。
- **趋势**：从提示技巧（2022）到训练目标（2024–2025 的 RLVR），从「平均加长」到「按难度自适应分配」；「深度思考」相对 2022 年的思维链，新就新在行为被训进权重、并配上了标签格式与预算控制。评测时永远先对齐采样协议与算力预算。

延伸阅读：推理系统侧的加速机制见[《投机解码》](/blog/投机解码-小模型打草稿大模型一次批改/)，底层结构见[《图解大模型（入门篇）》](/blog/图解大模型-一口气搞懂大模型的骨架/)，工程实战见[推理加速专栏](/inference/)。

## 9. 自测（答案点击展开）

<Expand title="Q1：思维 token 会参与注意力、写入 KV Cache 吗？产品把它藏起来，对模型意味着什么？">
会。思考 token 与答案 token 在模型看来是同一种 token，都进入上下文、参与每一步注意力、写入 KV Cache。产品界面「隐藏思考」只是不给用户看原文，对模型自身的计算没有任何影响；部分厂商不下发思考原文，是 API 产品层的设置。
</Expand>

<Expand title="Q2：2022 年论文里小模型用思维链没效果，为什么 R1 蒸馏后 15 亿参数的模型也能做 CoT？">
2022 年的结论有两个限定：一是「涌现」部分来自非连续指标的测量假象（Schaeffer）；二是它描述的是**未受推理训练的旧模型 + 提示词**的情形。R1 用长推理轨迹做 SFT（蒸馏），把分步推理的行为分布训进了小模型——说明这不是规模硬阈值，但小模型仍有能力天花板，最难任务上仍弱于大模型。
</Expand>

<Expand title="Q3：「让模型多写点思考过程总没坏处」对吗？把思考预算翻倍，正确率会翻倍吗？">
不对，也不会。思维链生效有前提（可串行分解、单步在能力内、后文真用前文）；简单任务上强制思考可能更差；长链存在倒 U 形——R1 蒸馏小模型在 MATH-500 上先升后降（82.2%→87.3%→70.3%），长链会跑题、错误累积。预算与正确率绝非线性关系，最难的题（pass@1≈0）加多少预算都救不回来。
</Expand>

<Expand title="Q4：用 RLVR 训练推理能力的四个步骤是什么？为什么数学和代码最先突破？">
四步：采样多个完整解答 → 程序判分（数学匹配答案、代码跑测试）→ 同题组内比较高低 → 调整权重让好轨迹更易被采样。数学和代码的最终答案可以被程序客观、廉价、无限规模化地判定（RLVR），不需要人标注推理过程；开放写作类任务答案难自动判分，仍需奖励模型，所以突破较晚。
</Expand>

<Expand title="Q5：模型给出了一段头头是道的思考，答案却是错的。这段思考能当它的「真实思路」吗？该怎么办？">
不能直接当真。思维链是外显的计算轨迹而非内心独白的录音：Turpin 实验显示模型会写推理迎合预设答案；但干预实验又表明篡改思考步骤常改变答案，说明它有部分因果作用。正确做法是把思考当**审计线索**：独立验算结论、换条路径复算、核验外部证据，而不是因为「过程看起来合理」就信任答案。
</Expand>

<Expand title="Q6：训练推理能力需要重新设计模型结构吗？有什么配套修改是必须的？">
不需要，主流路线只动权重——R1-Zero 在现成的 V3 基座上直接做 RL 就是证据，蒸馏也同样结构不动。必须配套的是：chat 模板加思考起止标签、RL 基础设施（可验证任务、组采样），以及「基座足够大且预训练过数学、代码」这个隐性前提。
</Expand>

<Expand title="Q7：模型怎么知道思考何时结束？「深度思考」和思维链是同一回事吗？">
思考段边界是 SFT 语料教出的概率规律——模型自己采样出结束标签后转入正式答案，不是外部信号，也不是硬状态机，偶尔会格式错乱、需要服务端兜底。机制上深度思考就是思维链；区别在前者是训练进权重、带标签格式和预算控制的默认模式，后者最初只是提示词技巧。
</Expand>
