# 1. 一句话讲清楚 Transformer
Transformer 本质上是一个函数：**输入一串 token ID，输出下一个 token 的概率分布**。

- 它由 Google 在 2017 年论文 [*Attention Is All You Need*](https://arxiv.org/abs/1706.03762) 提出，核心创新是 **Self-Attention（自注意力）**：让序列里任意两个位置直接交换信息，不再依赖 RNN/CNN 的递归或卷积。
- 它是 GPT、LLaMA、Gemini、DeepSeek、Qwen 等几乎所有现代大模型的骨架。
- 文本生成靠的是 **next-token prediction（下一个 token 预测）**：给一句话，预测最可能接在后面的那个词（或子词），然后把它拼回去再预测下一个，循环往复——这叫**自回归（autoregressive）**。

先给两个贯穿全文的「解剖样本」：

| 配置 | GPT-2 small（经典） | LLaMA 2 7B（现代） |
| --- | --- | --- |
| 参数量 | 124 M（1.24 亿） | 6.7 B（约 70 亿） |
| 隐藏维度 `d_model` | 768 | 4096 |
| Transformer 层数 `L` | 12 | 32 |
| 注意力头数 `H` | 12 | 32 |
| 每头维度 `head_dim` | 64 | 128 |
| FFN 中间维度 | 3072（4×） | 11008 |
| 词表大小 `V` | 50,257 | 32,000 |
| 位置编码 | 学习式（learned） | RoPE（旋转式） |
| 归一化 | LayerNorm | RMSNorm |
| FFN 激活 | GELU | SwiGLU |
| 注意力 | MHA | MHA（7B）/ GQA（70B、LLaMA 3） |

# 2. 第 1 步：分词 Tokenize

模型只认识数字，所以先把文本切成 **token**（一个词、子词或标点）（可能是一个词、一个子词或一个标点），再映射成词表里的 ID。主流分词算法是 **BPE（Byte Pair Encoding）**，思想极简：

```
初始:   l o w e r      # 从字符开始
第 1 轮: lo w e r      # l+o 共现最频繁 → 合并成 lo
第 2 轮: low e r       # lo+w 合并
第 3 轮: lower         # low+er 合并
```

高频词（the、is）会成为完整 token，低频词被拆成子词：`unhappiness → un + happ + iness`。三种主流分词库：

| 特性 | tiktoken（OpenAI） | SentencePiece（Google） | HF Tokenizers |
| --- | --- | --- | --- |
| 算法 | BPE（byte-level） | BPE / Unigram | BPE / WordPiece / Unigram |
| 实现 | Rust + Python | C++ + Python | Rust + Python |
| 用户 | GPT-4 / GPT-4o | LLaMA、T5、Gemma | BERT 及众多 HF 模型 |
| 中文 | byte-level 回退 | 原生支持 | 取决于模型 |

> **中文的坑**：英文有天然空格分词，中文没有。同一句「大语言模型的推理优化」，tiktoken 可能切 5 个 token，SentencePiece（LLaMA）可能切 7 个。这也是 Qwen、Yi 等中文模型特意扩充中文词表（Qwen2 词表 15 万+）的原因——同样内容更省 token、更快更便宜。


# 3. 第 2 步：词嵌入 + 位置编码

## 3.1 Token Embedding：ID → 稠密向量

查表得到每个 token 的向量。GPT-2 把每个 token 表示成 **768 维**向量，存在一个 `(50257, 768)` 的矩阵里——约 3900 万个参数；LLaMA 2 是 `(32000, 4096)`。语义相近的词在这个高维空间里距离更近。

## 3.2 位置编码：为什么必须有

Self-Attention 本身**对顺序无感**——把句子里的词打乱，每个 token 聚合到的信息集合不变。但「狗咬人」和「人咬狗」天差地别。所以必须显式注入「你是第几个 token」。三种主流做法：

| 方式 | 代表模型 | 做法 | 特点 |
| --- | --- | --- | --- |
| 学习式 PE | GPT-2 | 直接训练一个位置嵌入矩阵，和 token 嵌入**相加** | 简单，但外推到更长序列较弱 |
| 正弦 PE | 原始 Transformer | 用 sin/cos 固定函数生成位置向量相加 | 无需学习，可外推 |
| **RoPE** 旋转位置编码 | LLaMA / Qwen / DeepSeek | 把位置编码成**旋转角度**，通过乘法作用在 Q、K 上（不作用于 V） | 长上下文外推好，现代 LLM 标配 |

Embedding 阶段的代码（以 GPT-2 配置为例）：

```python
import torch
import torch.nn as nn

class Config:
    vocab = 50257     # 词表大小 V
    d = 768           # 隐藏维度
    max_len = 1024    # 最大序列长度
cfg = Config()

# token 嵌入：查表 [V, d]；位置嵌入（GPT-2 学习式）：[max_len, d]
tok_emb = nn.Embedding(cfg.vocab, cfg.d)
pos_emb = nn.Embedding(cfg.max_len, cfg.d)

ids = torch.tensor([[1234, 5678, 9012]])   # [batch=1, n=3]，3 个 token ID
pos = torch.arange(ids.size(1))             # 位置 [0, 1, 2]

x = tok_emb(ids) + pos_emb(pos)             # 逐位置相加 → [1, 3, 768]
print(x.shape)                              # torch.Size([1, 3, 768])
```

RoPE 的核心思想是把向量每相邻两维看作平面坐标，按位置旋转一个角度（频率不同），下面是简化实现：

```python
def precompute_rope(head_dim, max_len, base=10000.0):
    inv_freq = 1.0 / (base ** (torch.arange(0, head_dim, 2).float() / head_dim))
    t = torch.arange(max_len).float()
    freqs = torch.outer(t, inv_freq)              # [max_len, head_dim/2]
    return torch.cos(freqs), torch.sin(freqs)

def apply_rope(x, cos, sin):
    # x: [batch, heads, n, head_dim]
    cos, sin = cos[: x.size(2)], sin[: x.size(2)]
    x1, x2 = x[..., 0::2], x[..., 1::2]           # 相邻两维配对
    rot = torch.stack([x1 * cos - x2 * sin,
                       x1 * sin + x2 * cos], dim=-1)
    return rot.flatten(-2)                        # 旋转后形状不变
```

<Expand title="扩展阅读：GPT-2 可学习位置编码 vs RoPE 详细对比">

两种典型的位置编码路线。**GPT-2 用可学习的绝对位置编码**：给每个位置准备一个可训练向量 $P_t$（`nn.Embedding(max_len, d)`），直接加到词嵌入

$$
h_t = E[x_t] + P_t
$$

位置信息在进网络前一次性加入，本质是**绝对位置**——模型只知道"我是第 5 个词"，相对距离要自己间接学。

**RoPE 用旋转位置编码**：在每层注意力里对位置 $t$ 的 $\mathrm{Q}$、$\mathrm{K}$ 按与位置相关的角度旋转（相邻两维配对，多维不同频率）：

$$
\tilde{q}_t = R_{t}\,q_t,\qquad \tilde{k}_t = R_{t}\,k_t
$$

旋转矩阵满足 $R_t^\top R_s = R_{s-t}$，于是注意力点积只依赖**相对位置** $(s-t)$：

$$
\tilde{q}_t^\top \tilde{k}_s = q_t^\top R_{s-t}\,k_s
$$

V 不旋转（它是"内容"，不需要位置方向）。

| 对比维度 | GPT-2 可学习位置编码 | RoPE 旋转位置编码 |
| --- | --- | --- |
| 位置表示 | 绝对位置（可训练向量） | 相对位置（旋转角差） |
| 注入方式 | 加到**输入嵌入**（一次） | 每层对 **Q/K 旋转**（乘法） |
| 作用对象 | 所有后续层 | 仅注意力的 Q、K（V 不动） |
| 额外参数 | 有：`max_len × d` 位置表 | **无**：角度由固定频率算出 |
| 外推性（超出训练长度） | 差：超长位置没有对应向量 | 好：可配合 NTK / YaRN 扩到更长上下文 |
| 相对距离感知 | 间接（靠模型自己学） | 天然内建（点积只与相对位置有关） |
| 代表模型 | GPT-2、BERT（早期） | LLaMA、Qwen、DeepSeek、Mistral |

一句话：**GPT-2 把位置当"要学的词表"，额外训一张绝对位置表；RoPE 零参数，用旋转几何让注意力自带相对位置感知、更易外推**——现代大模型几乎都用 RoPE。

</Expand>

# 4. 第 3 步：Transformer Block

这是 Transformer 的核心，对应总览图里堆叠 N 次的大块。**自注意力和前馈网络都在它内部**——每个 Block 内部数据自下而上：先经过①多头自注意力（词互相交换信息），再经过②前馈网络（逐词提炼特征），各带一次归一化与残差连接。下面先看整体结构，再逐层拆开注意力。

## 4.1 一个 Block 的整体结构

单个 Block 是固定积木，整个模型靠它堆叠 `L` 次（GPT-2 堆 12 次，LLaMA 2 堆 32 次）。现代模型采用 **Pre-Norm**（先归一化再进子层），并在每个子层外包一条**残差连接**：

<BlockDetailFigure />

两个关键配角：

- **残差连接（Residual）**：`x = x + 子层(Norm(x))`，让梯度有一条「高速公路」直通浅层，缓解深层网络的梯度消失，这是能堆几十上百层的前提。
- **归一化（Norm）**：稳定数值分布、加速收敛。

## 4.2 Self-Attention：Q / K / V 与公式

用 Q（Query，查询）/ K（Key，键）/ V（Value，值）做「带权重的搜索」——Q 是搜索词、K 是标题、V 是内容，相关性高的多取信息；把它写成数学，就是最核心的一个公式：

$$
\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{Q\,K^{\top}}{\sqrt{d_k}}\right)V
$$

一步步拆开（$n$ = token 数，$d$ = 向量维度，$\mathtt{@}$ 表示矩阵乘法）：

```text
Q = X @ W_q      # [n, d] → [n, d]
K = X @ W_k      # [n, d] → [n, d]
V = X @ W_v      # [n, d] → [n, d]

scores = Q @ Kᵀ            # [n, d] @ [d, n] → [n, n]   ← O(n²)
scores = scores / √d_k     # 缩放
weights = softmax(scores)  # 每行归一化成概率，行内和为 1 → [n, n]
output = weights @ V       # [n, n] @ [n, d] → [n, d]
```

写成矩阵形式，其中 $d_k$ 是每头维度，$K^{\top}$ 是 K 的转置：

$$
Q=XW_q,\quad K=XW_k,\quad V=XW_v,\qquad
\mathrm{weights}=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right),\qquad
\mathrm{output}=\mathrm{weights}\,V
$$

| 步骤 | 操作 | shape | 含义 |
| --- | --- | --- | --- |
| ① | `Q @ Kᵀ` | `[n, d]→[n, n]` | 每个 token 与每个 token 的相关性分数 |
| ② | `/ √d_k` | `[n, n]` | 缩放，防止点积过大 |
| ③ | causal mask | `[n, n]` | 把「未来」位置置为 −∞ |
| ④ | `softmax` | `[n, n]` | 每行变成和为 1 的注意力权重 |
| ⑤ | `@ V` | `[n, n]→[n, d]` | 按权重聚合所有 token 的信息 |

<AttentionFlowFigure />

*图 2：Scaled Dot-Product Attention。Q 和 K 先算出 `[n,n]` 的相关性矩阵，经缩放、掩码、softmax 后，再与 V 相乘完成信息聚合。*

<Expand title="补充阅读：为什么 Q·Kᵀ 这个矩阵乘得到的就是「相关性分数」">

核心直觉：**两个向量的点积，衡量它们方向的一致程度**——越同向（夹角越小）点积越大，越垂直点积越接近 0。

把每个 token 的查询向量 $q_i$ 和所有词的键向量 $k_j$ 做点积：

$$
s_{ij}=q_i^{\top}k_j=\sum_{m=1}^{d_k} q_{i,m}\,k_{j,m}
$$

- $s_{ij}$ 大 → 位置 $i$ 的"查询"与位置 $j$ 的"键"语义上对得上 → 注意力多取位置 $j$ 的内容；
- $s_{ij}$ 小（或为负）→ 两者无关 → 权重接近 0。

这和信息检索里的**检索打分**是一回事：把文档和查询都表示成向量，用余弦相似度/点积排序，点积最大的文档最相关。注意力只不过对**每个词并行做一次检索**，检索库就是同一句话里所有词的 K。

一次矩阵乘把 $n$ 个查询 × $n$ 个键的两两点积全部算出来：

$$
S=QK^{\top},\qquad S_{ij}=q_i^{\top}k_j
$$

得到的 $[n,n]$ 矩阵里，第 $i$ 行第 $j$ 列就是"词 $i$ 该看词 $j$ 多少"。随后的 softmax 把这一行归一化成和为 1 的权重，再用它加权 $V$：

$$
\mathrm{output}_i=\sum_{j}\text{softmax}_j\!\left(\frac{s_{ij}}{\sqrt{d_k}}\right)\,v_j
$$

所以"矩阵乘得到相关性"并不是玄学——**点积即相似度**，$QK^{\top}$ 就是在批量计算所有词对之间的语义相似度。

</Expand>

<Expand title="进一步阅读：① 为什么要除以 √d_k 缩放　② 因果掩码长什么样">

**① 为什么除以 $\sqrt{d_k}$。** 把 Q、K 分量看作均值 0、方差 1 的独立随机变量，点积 $s=q\cdot k=\sum_{i=1}^{d_k} q_i k_i$ 的方差等于 $d_k$：

$$
\operatorname{Var}[q\cdot k]=d_k
$$

维度越大，点积数值越大：$d_k=128$（LLaMA 7B）时轻易到十几、几十，会把 softmax 推成接近 one-hot 的饱和态、梯度趋近 0，训练停滞。除以 $\sqrt{d_k}$ 把方差归一回 1：

$$
\operatorname{Var}\!\left[\frac{q\cdot k}{\sqrt{d_k}}\right]=1
$$

无论 $d_k$ 多大，分数尺度都稳定——这就是 **scaled dot-product** 名字的由来。

**② 因果掩码（Causal Mask）。** 生成模型只能看过去、不能偷看未来：softmax 前把 $[n,n]$ 分数矩阵的**上三角（未来位置）置为 $-\infty$**，softmax 后这些位置权重变 0。以 3 个 token 为例（✓ 可关注，✗ 被掩码）：

| 当前 token | token₁ | token₂ | token₃ |
| --- | :-: | :-: | :-: |
| token₁ | ✓ | ✗ | ✗ |
| token₂ | ✓ | ✓ | ✗ |
| token₃ | ✓ | ✓ | ✓ |

这保证词 $i$ 的输出只依赖它和它之前的词，是 GPT 类自回归模型的关键。

</Expand>

## 4.3 Self-Attention 的 PyTorch 实现

```python
import torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q, K, V: [batch, heads, n, head_dim]
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / (d_k ** 0.5)   # [B, H, n, n]
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    weights = F.softmax(scores, dim=-1)                # 每行归一化
    return weights @ V                                 # [B, H, n, head_dim]

# 因果掩码：下三角为 1（可看自己和过去），上三角为 0
n = 3
causal_mask = torch.tril(torch.ones(n, n)).view(1, 1, n, n)
# tensor([[[[1., 0., 0.],
#           [1., 1., 0.],
#           [1., 1., 1.]]]])
```

> PyTorch 2.0+ 内置了融合优化版 `F.scaled_dot_product_attention(Q, K, V, is_causal=True)`，底层会自动调用 FlashAttention / memory-efficient kernel，生产代码直接用它即可。

## 4.4 Multi-Head Attention：为什么要多头

一个注意力头只能学一种「关注模式」。把 `d` 维拆成 `H` 个头、每头 `head_dim = d / H` 维，**每个头独立做注意力**，就能同时从不同视角看句子：有的头盯相邻词（语法），有的头盯主谓一致，有的头盯长距离指代。计算量和单头基本不变，但表达能力更强。

- GPT-2：768 维 = 12 头 × 64 维
- LLaMA 2：4096 维 = 32 头 × 128 维

数据流（以 GPT-2、`n` 个 token 为例）：

```
X [n, 768]
  │  三个投影 Wq Wk Wv（可合并成一个 768→3·768 的线性层）
  ▼
Q,K,V [n, 768]  ──拆成 12 头──►  [n, 12, 64] ──转置──► [12, n, 64]（每头独立）
  │
  ▼  每头各自 scaled-dot-product attention（并行）
[n, 12, 64]  ──拼回──►  [n, 768]
  │  输出投影 Wo
  ▼
[n, 768]
```

## 4.5 多头注意力的代码实现

```python
class MultiHeadSelfAttention(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.H, self.hd = cfg.n_heads, cfg.head_dim
        self.qkv = nn.Linear(cfg.d, 3 * cfg.d)      # 合并 Q/K/V 投影
        self.proj = nn.Linear(cfg.d, cfg.d)         # 输出投影 Wo

    def forward(self, x):
        B, n, _ = x.shape
        qkv = self.qkv(x).reshape(B, n, 3, self.H, self.hd)
        qkv = qkv.permute(2, 0, 3, 1, 4)           # [3, B, H, n, hd]
        Q, K, V = qkv[0], qkv[1], qkv[2]           # 各 [B, H, n, hd]

        mask = torch.tril(torch.ones(n, n, device=x.device)).view(1, 1, n, n)
        out = scaled_dot_product_attention(Q, K, V, mask)   # [B, H, n, hd]

        out = out.transpose(1, 2).reshape(B, n, -1)        # 拼头 → [B, n, d]
        return self.proj(out)
```

## 4.6 MHA / GQA / MQA：省 KV Cache 的演进

推理时要缓存历史 token 的 K、V（第 7 节讲原因）。现代模型通过让多个 Q 头共享 K/V 头来压缩缓存：

| 方案 | Q 头 | K/V 头 | KV Cache | 精度 | 代表 |
| --- | :-: | :-: | --- | --- | --- |
| **MHA** 多头 | 32 | 32 | 1×（基准） | 最好 | GPT-2、LLaMA 2 7B |
| **GQA** 分组查询 | 32 | 8 | 约 1/4 | 损失 &lt;1% | LLaMA 3、LLaMA 2 70B、Mistral、Qwen2 |
| **MQA** 多查询 | 32 | 1 | 约 1/32 | 略降 | 早期 PaLM、Falcon |

```
MHA:  Q 32 头 │ K 32 头 │ V 32 头
GQA:  Q 32 头 │ K  8 头 │ V  8 头   （每 4 个 Q 头共享 1 组 KV）
MQA:  Q 32 头 │ K  1 头 │ V  1 头   （所有 Q 头共享同 1 组 KV）
```

GQA 已基本成为现代 LLM 的标配；DeepSeek 还进一步提出 MLA（多头潜在注意力）把 K/V 压成低维潜变量。

> 🔮 **后续预告**：注意力"头"的演进是一条独立且精彩的主线——**MHA（2017）→ MQA（2019）→ GQA（2023）→ MLA（DeepSeek）**，本质都在回答同一个问题：**怎么在几乎不损效果的前提下，大幅压缩推理时最占显存、最影响吞吐的 KV Cache**。我会单开一篇《注意力头的演进：从 MHA 到 MLA》，讲清它们的取舍、共享粒度，以及 MLA 如何用低秩潜变量把 KV Cache 再压一个数量级。感兴趣的可以在 [推理加速实战](/inference/) 里先看这些机制怎么落到 vLLM。

## 4.7 归一化：LayerNorm vs RMSNorm

**为什么要归一化？** 几十层网络里，信号逐层相乘叠加，激活值的尺度可能爆炸（越来越大）或消失（越来越小），导致训练不稳、梯度坏掉。归一化把每个 token 的向量拉回一个稳定的数值范围，让深层网络可训练。和 BatchNorm 沿 batch 维统计不同，Transformer 用的是 **LayerNorm**——对**每个样本自己**的特征维做归一化，不依赖 batch，天然适合变长序列。

| | LayerNorm（GPT-2、BERT） | RMSNorm（LLaMA、Qwen、DeepSeek） |
| --- | --- | --- |
| 做什么 | 减均值（居中）→ 除标准差（缩放）→ $\gamma$ 缩放、$\beta$ 平移 | 只按均方根缩放，**不减均值**，可学参数只有 $\gamma$ |
| 统计量 | 均值 $\mu$ + 方差 $\sigma^2$ | 均方根 RMS（省去均值） |
| 可学参数 | $\gamma,\ \beta$（各 d 个） | 只有 $\gamma$（d 个），省一半 |
| 计算量 | 两次 reduce（均值+方差） | 一次 reduce（平方均值） |
| 公式 | $\hat{x}=\dfrac{x-\mu}{\sigma}\,\gamma+\beta$ | $\hat{x}=\dfrac{x}{\mathrm{RMS}(x)}\,\gamma,\ \ \mathrm{RMS}(x)=\sqrt{\dfrac{1}{d}\sum_{i=1}^{d}x_i^2+\epsilon}$ |

**RMSNorm 为什么成为现代大模型标配？** 它的核心观察是：LayerNorm 里**「减均值」这一步作用很小，真正起稳定作用的是缩放**。于是 RMSNorm 直接丢掉均值居中（re-centering），只保留重新缩放（re-scaling），用均方根

$$
\mathrm{RMS}(x)=\sqrt{\frac{1}{d}\sum_{i}x_i^2}
$$

来度量向量的「大小」，再除以它。带来的好处：

- **更快**：只需要一次平方均值，省去了均值计算；在大模型里这部分 kernel 开销可观。
- **省参数/显存**：没有偏置 $\beta$，可学参数减半。
- **数值更稳、效果不掉**：LLaMA、T5、PaLM、Qwen、DeepSeek 等的实践表明，RMSNorm 训练稳定性和最终效果与 LayerNorm 基本持平。

**Pre-Norm vs Post-Norm**：GPT-2 时代把 Norm 放在子层**之后**（Post-Norm：$x=\mathrm{Norm}(x+\mathrm{Sublayer}(x))$），深层容易梯度不稳，需要 warmup 等技巧。现代大模型普遍用 **Pre-Norm**——先 Norm 再进子层、残差走「干净」的捷径：

$$
x_{\text{out}}=x+\mathrm{Sublayer}\big(\mathrm{Norm}(x)\big)
$$

残差通路不经过归一化，梯度可以顺畅直达浅层，配合 RMSNorm，几十上百层也能稳定训练（本文 Block 详图里就是 Pre-Norm）。

```python
class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d))   # γ（没有 β）
        self.eps = eps
    def forward(self, x):
        # 均方根：平方 → 特征维求均值 → 加 eps 防除零 → rsqrt
        norm = x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        return norm * self.weight                   # 再乘可学习缩放 γ

# 对比 LayerNorm（GPT-2 用）：多了减均值和偏置
# nn.LayerNorm(d)  内部：(x - mean) / sqrt(var + eps) * γ + β
```

> 📐 归一化是机器学习的通用基础（Z-score 标准化、BatchNorm、LayerNorm、RMSNorm 的统计方向、数学直觉与工业做法），在<a href="/ml/">图解机器学习</a>第 10 节《归一化：让数值稳定的关键》有图文讲解；本节聚焦它在 Transformer 里的用法。

## 4.8 前馈网络 FFN

如果说注意力负责**在 token 之间搬运、混合信息**，那 FFN（Feed-Forward Network，也叫 MLP）负责**对每个位置独立地做深加工和存储知识**。它对每个 token 用**相同**的权重、但**各自独立**地计算（不像注意力那样跨 token 交互）。可以理解为：注意力把相关词的信息「看」过来之后，FFN 再在每个位置上做一次非线性的特征变换与记忆。

**结构：升维 → 非线性激活 → 降维。** 为什么要先升维？先用一个大 4 倍左右的中间层把特征投影到更高维空间，在那里施加非线性，模型能表达更复杂的模式，再压回原维度：

- **GPT-2（GELU）**：$768 \to 3072$（4 倍）$\to$ GELU $\to 768$
- **LLaMA（SwiGLU）**：门控结构，用 3 个矩阵 `gate / up / down`，中间维度 11008

两种形式的数学表达：

$$
\text{FFN}_{\text{GPT-2}}(x)=W_2\,\sigma_{\text{GELU}}(W_1 x+b_1)+b_2
$$

$$
\text{FFN}_{\text{SwiGLU}}(x)=W_{\text{down}}\Big(\ \mathrm{SiLU}(W_{\text{gate}}x)\odot (W_{\text{up}}x)\ \Big)
$$

其中 SiLU（Swish）$\mathrm{SiLU}(x)=x\,\sigma(x)$ 是一个平滑的激活；$\odot$ 是逐元素相乘。**SwiGLU 的门控直觉**：`gate` 分支经过 SiLU 产出一个 0~1 的「开关」，去逐元素调节 `up` 分支哪些特征该通过——类似 LSTM/GRU 的门控，让信息流动更可控。实践中 SwiGLU 通常比 GELU 略好，代价是多一个投影矩阵，所以 LLaMA 把中间维度从 $4d$ 缩到约 $\tfrac{2}{3}\cdot 4d$（即 11008）来保持参数量大致相当。

```python
class GPT2_MLP(nn.Module):                       # GPT-2：两层线性 + GELU
    def __init__(self, cfg):
        super().__init__()
        self.fc1 = nn.Linear(cfg.d, cfg.ffn)    # 768 → 3072（升维）
        self.fc2 = nn.Linear(cfg.ffn, cfg.d)    # 3072 → 768（降维）
    def forward(self, x):
        return self.fc2(F.gelu(self.fc1(x)))

class SwiGLU_FFN(nn.Module):                    # LLaMA：门控 FFN
    def __init__(self, d, hidden):
        super().__init__()
        self.gate = nn.Linear(d, hidden, bias=False)
        self.up   = nn.Linear(d, hidden, bias=False)
        self.down = nn.Linear(hidden, d, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))   # silu 即 Swish
```

**两个值得记住的点：**

- **FFN 是参数量大头**。LLaMA 2 7B 每层 FFN 约 135M 参数、注意力投影约 67M——FFN 占了约 63%。经验研究也认为**事实性知识主要储存在 FFN 的权重里**（可把它看成一张超大的 key-value 记忆表），注意力更多负责「检索与路由」。
- **块内顺序是先注意力后 FFN**：$x \to$ 注意力（混合上下文）$\to$ FFN（逐点深加工），各带 Pre-Norm 和残差，然后进入下一层。

> 到这里，一个 Transformer Block 的四个零件——多头注意力、残差+归一化、FFN——就齐了。把它堆叠 N 次，就是整个骨干网络。

## 4.9 拼装一个完整 Block

```python
class TransformerBlock(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.ln1  = nn.LayerNorm(cfg.d)    # LLaMA 换成 RMSNorm
        self.attn = MultiHeadSelfAttention(cfg)
        self.ln2  = nn.LayerNorm(cfg.d)
        self.ffn  = GPT2_MLP(cfg)          # LLaMA 换成 SwiGLU_FFN

    def forward(self, x):
        x = x + self.attn(self.ln1(x))     # Pre-Norm + 残差
        x = x + self.ffn(self.ln2(x))
        return x
```

# 5. 第 4 步：Final Norm → LM Head

所有 Block 处理完后，取**最后一个位置**的向量，映射到词表大小得到 **logits（原始分数，可正可负，未归一化）**：

所有 Block 处理完后，取**最后一个位置**的向量，映射到词表大小得到 **logits（原始分数，可正可负，未归一化）**，再 softmax 成概率：

```
[n, d] ──Final Norm──► [n, d] ──Linear Head──► [n, V]
                                              取最后位置 → [V] 个 logits
                                              ──softmax──► 每个 token 的概率
```

```python
class GPT(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.tok_emb = nn.Embedding(cfg.vocab, cfg.d)
        self.pos_emb = nn.Embedding(cfg.max_len, cfg.d)
        self.blocks  = nn.ModuleList([TransformerBlock(cfg) for _ in range(cfg.n_layers)])
        self.ln_f    = nn.LayerNorm(cfg.d)
        self.head    = nn.Linear(cfg.d, cfg.vocab, bias=False)   # LM Head

    def forward(self, ids):                   # ids: [B, n]
        B, n = ids.shape
        x = self.tok_emb(ids) + self.pos_emb(torch.arange(n, device=ids.device))
        for blk in self.blocks:
            x = blk(x)
        x = self.ln_f(x)
        logits = self.head(x)                # [B, n, V]
        return logits[:, -1, :]              # 只取最后位置 → [B, V]
```


# 6. 第 5 步：Softmax 与采样

**采样**决定了输出的「确定 vs 随机」。三个旋钮：

| 机制 | 作用 | 调节效果 |
| --- | --- | --- |
| **temperature** 温度 | logits 先除以 T，再 softmax（$T\to0$ 趋近贪心） | $T<1$ 分布更尖锐、更确定保守；$T>1$ 更平坦、更随机「有创意」；$T=1$ 原样 |
| **top-k** | 只在概率最高的 k 个 token 里采 | k 越小越保守 |
| **top-p**（nucleus） | 只在累计概率达到 p 的最小集合里采 | p 越小越保守 |

```python
def sample(logits, temperature=1.0, top_k=None, top_p=None):
    logits = logits / temperature
    probs = F.softmax(logits, dim=-1)

    if top_k:                                  # top-k 截断
        v, _ = torch.topk(probs, min(top_k, probs.size(-1)))
        probs[probs < v[..., [-1]]] = 0
    if top_p:                                  # top-p（nucleus）截断
        sp, idx = torch.sort(probs, descending=True)
        sp[(sp.cumsum(-1) - sp) > top_p] = 0
        probs = torch.zeros_like(probs).scatter_(-1, idx, sp)

    probs = probs / probs.sum(-1, keepdim=True)
    return torch.multinomial(probs, 1)         # 按概率抽一个 token
```

生成时把采样出的 token 拼回输入，重复 forward，就是自回归生成。

# 7. 规模直觉：参数怎么数、注意力有多贵

## 7.1 参数都在哪

**GPT-2 small（约 124M）**：

| 组件 | 计算 | 参数量 |
| --- | --- | --- |
| Token Embedding | 50257 × 768 | ≈ 38.6 M |
| Position Embedding | 1024 × 768 | ≈ 0.8 M |
| 每层 Attention | (768×2304) + (768×768) | ≈ 2.4 M |
| 每层 MLP | 2 × (768×3072) | ≈ 4.7 M |
| 12 层合计 | 12 × (2.4+4.7) | ≈ 85 M |

**LLaMA 2 7B（每层，d=4096、ffn=11008）**：

| 组件 | 计算 | 参数量 | 占比 |
| --- | --- | --- | --- |
| Q/K/V/O 投影 | 4 × 4096² | 67 M | 31% |
| FFN（gate/up/down） | 3 × 4096 × 11008 | 135 M | 63% |
| RMSNorm | 2 × 4096 | 8 K | ~0% |

每层约 202M，32 层 ≈ 6.5B，加上 Embedding/Head 约 **6.7B ≈ 7B**。一个经验：**FFN 是参数量大头**，而不是注意力。FP16 下 1B 参数 ≈ 2GB 显存，7B 权重约 14GB。

## 7.2 注意力是 O(n²)

$QK^\top$ 生成 $[n,n]$ 矩阵，n 是序列长度。长度翻倍，注意力的计算量和显存变 **4 倍**：

| 序列长度 | 注意力矩阵元素 | 单层单头显存(FP16) | 相对 4K |
| --- | --- | --- | --- |
| 2K | 4 M | 8 MB | — |
| 4K | 16 M | 32 MB | 1× |
| 32K | 1024 M | 2 GB | 64× |
| 128K | 16384 M | 32 GB | 1024× |

这就是长文本又慢又贵、需要 FlashAttention、PagedAttention 等优化的根本原因。

## 7.3 KV Cache：自回归为什么要缓存

不用缓存时，每生成一个 token 都要把整段历史重算一遍注意力；而历史 token 的 K、V 其实不变：

```text
无缓存：
  输入 [A,B,C]      → 算全部 → 生成 D
  输入 [A,B,C,D]    → 又算全部 → 生成 E
  输入 [A,B,C,D,E]  → 又算全部 → 生成 F

有 KV Cache：
  输入 [A,B,C]  → 缓存 K_ABC,V_ABC → 生成 D
  只输入 [D]    → 算 K_D,V_D，拼上缓存 → 生成 E
  只输入 [E]    → 算 K_E,V_E，拼上缓存 → 生成 F
```

缓存大小 `= 2（K和V）× 层数 × KV头数 × head_dim × 序列长度 × batch`，随上下文和并发暴涨。这正是 GQA/MQA（省 KV 头）、PagedAttention（按页管理显存）存在的意义——本站 [推理加速实战](/inference/) 有 vLLM 源码级解读。

# 8. 一张速查表总结
**Transformer Block 内的数据流（shape 以 GPT-2 为例）**：

| 阶段 | 操作 | shape 变化 |
| --- | --- | --- |
| 输入 | token ID | `[n]` |
| Embedding | tok + pos | `[n] → [n, 768]` |
| Attention | QKV 投影 | `[n,768] → [n,12,64]` |
| Attention | QKᵀ/scale/mask/softmax | `→ [12, n, n]` |
| Attention | ·V + 拼头 + 输出投影 | `→ [n, 768]` |
| FFN | 升维 → GELU → 降维 | `[n,768]→[n,3072]→[n,768]` |
| 输出 | Final Norm + Head | `[n,768] → [n, 50257]` |
| 采样 | softmax + temperature/top-k/top-p | `[50257] → 1 个 token` |

**经典 vs 现代 Decoder 的差异**：

| 维度 | GPT-2（2019） | LLaMA 2（2023） |
| --- | --- | --- |
| 位置编码 | 学习式相加 | RoPE 旋转（作用于 Q/K） |
| 归一化 | LayerNorm | RMSNorm |
| FFN | GELU，2 矩阵 | SwiGLU，3 矩阵门控 |
| 注意力 | MHA | MHA / GQA |
| 偏置 bias | 线性层多带 bias | 大多去掉 bias |

**核心术语**：token / embedding / projection（=Linear）/ Q·K·V / self-attention / multi-head / causal mask / FFN(MLP) / residual / LayerNorm·RMSNorm / RoPE / SwiGLU·GELU / GQA / logits / softmax / KV Cache。
