GPT、LLaMA、DeepSeek、Qwen……这些「大模型」（LLM，大语言模型）名字不同，骨架却几乎是同一个东西——Transformer。这一章用图讲清：大模型到底在干什么，Transformer 又是怎么做到的。

1. 大模型只会一件事：预测下一个词

听起来不可思议，但所有聊天、写作、写代码的能力，都来自一个极其简单的机制——给定前面的词，猜下一个词最可能是什么（next-token prediction）。猜对了，就把这个词接到后面，再猜下一个，循环往复，这叫自回归（autoregressive）：

🎯 关键：模型输出的不是某个确定的词，而是词表里每个词的概率分布（「很」70%、「真」20%、「不」5%……），再按概率采样。所谓「 temperature 调创造力」，调的就是这个分布的尖锐程度。

3. 文字怎么进模型：分词与嵌入

模型只懂数字，所以先把文本切成 token（词或子词），每个 token 对应一个 ID，再查表换成一个向量（嵌入 embedding）。高频词是一个整体，低频词被拆成子词：

还要加位置编码——注意力本身分不清「狗咬人」和「人咬狗」，必须显式告诉它词的顺序（现代模型用 RoPE 旋转位置编码）。

4. 自注意力：让每个词去「看」别的词

这是 Transformer 最核心、也是取代 RNN/CNN 的创新。每个词根据和其他词的相关程度，按权重把它们的信息「取」过来。用三个向量理解，最好记的是搜索引擎类比：

向量搜索类比作用
Q（Query 查询）你输入的搜索词当前词「想找什么」
K（Key 键）每个网页的标题每个词「能被什么匹配」
V（Value 值）网页的实际内容真正取走聚合的信息

拿「小猫追着它的尾巴跑，它很开心」举例，第二个「它」指的是谁？注意力会学到「它」应该强烈关注「小猫」：

计算上就是一次带权重的平均，核心公式只有一行：

# Q/K/V 都是矩阵；@ 是矩阵乘法，softmax 把分数变成和为 1 的权重
权重 = softmax( Q @ K.T / √d )      # [n, n]：每个词对每个词的关注程度
输出 = 权重 @ V                      # [n, d]：按权重聚合信息
⚡ 为什么注意力这么强？任意两个词之间的距离都是 O(1)——「它」能直接看到隔了好几个词的「小猫」，不像 RNN 要一步步传。代价是计算量随句长 平方增长 O(n²)，这也是长文本又慢又贵、需要推理优化的根本原因（见推理加速实战）。

5. 多头注意力与一个 Block 的全貌

单个「头」只能学一种关注模式。把向量拆成 多个头并行（GPT-2 是 12 头、LLaMA 是 32 头），有的头盯语法、有的头盯指代、有的头盯相邻词，最后拼起来：

一个完整 Block 里，注意力负责词与词之间通信，前馈网络（FFN）负责逐个词提炼特征/存知识，再用归一化稳数值、残差连接让几十层堆得动：

x = x + 注意力(归一化(x))    # 残差：输入直接加回输出，梯度能直通浅层
x = x + FFN(归一化(x))       # FFN：升维 → 激活 → 降维，参数量占大头

6. 大模型是怎么「炼成」的：三个阶段

同样一个 Transformer，要变成会聊天的助手，要经过三步：

阶段数据目标类比
预训练几 T token 的互联网文本学会语言、事实、推理的底座读完一座图书馆
监督微调 SFT几万~百万条「指令→回答」学会按指令格式回答做往届真题
RLHF 对齐人类对回答的偏好排序更有帮助、无害、符合偏好教练按你的表现打分纠正
🧠 一个常被忽略的事实：预训练完成后，模型其实只是个「接话茬」的补全器；是 SFT 和 RLHF 让它从「续写文本」变成「回答问题的助手」。

7. 训练 vs 推理：为什么「推理」是一门大学问

训练（training）是用海量数据调参数，一次投入、极其昂贵；推理（inference）是训练好之后每次回答用户，要跑亿万次、直接决定成本和速度。

训练推理
干什么反向传播更新参数只做前向，逐词生成
频率几次亿万次（每个用户每次提问）
瓶颈算力（GPU 集群）显存带宽、KV Cache、批处理
关心收敛、效果吞吐、延迟、显存、成本

推理时最典型的难题是 KV Cache：生成每一个新词都要用到前面所有词的 Key/Value，缓存它们能避免重复计算，但会随上下文长度暴涨显存；再加上注意力本身 O(n²)，长文本和高并发就成了显存灾难。这正是 PagedAttention、连续批处理、量化、GQA、FlashAttention 等技术存在的意义。
